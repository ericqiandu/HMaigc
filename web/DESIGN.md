# Web UI 执行标准

本文件把工作区根目录 `Design.md` 映射为 Web 应用可直接执行的规则。根目录 `Design.md` 始终是视觉真源；本文件不得与其冲突。

## 当前推广方式

- 新视觉标准通过 `WorkspacePage` 自动挂载 `.workspace-ui-scope`，并显式覆盖独立的 `.settings-workspace-page`。
- `src/styles/design-tokens.css` 是 Web 视觉 Token 的唯一原始值来源；`globals.css`、`workspace-ui.css` 与业务样式只能消费语义 Token，不新增页面私有的颜色、圆角、阴影、动效或层级值。
- 工作台统一由 `AppWorkspaceShell` 挂载 `WorkspaceTopBar`：左侧展示后台站点配置中的 Logo 与站点名称，右侧展示真实公告、积分、会员入口和账户菜单；页面不得各自复制顶栏。
- 当前标准应用于项目、画布列表、任务、素材、技能、设置、团队、积分工作区与管理后台。
- 管理后台保留独立的侧栏信息架构和运营密度，但必须通过 `.admin-workspace.workspace-ui-scope` 继承同一套语义颜色、字体、内容宽度、控件高度与响应式标准；后台专属映射集中维护在 `src/pages/admin/admin-workspace.css`。
- 首页、会员购买页和画布编辑器拥有独立的信息架构，不得无选择地继承工作区布局规则。
- 页面业务、接口和权限不因视觉重构而改变。没有真实后端能力的按钮不得为了复刻参考站而伪造。

## 字体层级

| 角色       | 字号 |    字重 | 行高 |
| ---------- | ---: | ------: | ---: |
| 页面标题   | 16px |     600 | 22px |
| 卡片标题   | 14px |     600 | 20px |
| 正文与控件 | 14px | 400–500 | 20px |
| 辅助信息   | 12px |     400 | 17px |
| 紧凑元数据 | 11px |     400 | 16px |

- 全站统一使用 `-apple-system, BlinkMacSystemFont, PingFang SC, Inter, HarmonyOS Sans SC, Noto Sans SC, Microsoft YaHei, sans-serif` 系统优先字体栈；不下载网页字体，不为标题引入第二套字体。
- 同一层级不得通过任意 Tailwind 字号重复创造新规格。

## 间距与尺寸

- 基础间距单位为 4px，常用值仅限 4、8、12、16、24、32、40、48、64、80px；业务样式不得再引入 20px 等额外间距值。
- 桌面端工作台控制高度统一为 36px。
- 移动端主要操作、搜索和筛选控件统一为至少 44px 高。
- 图标按钮的可点击区域不得小于 32×32px；移动端主要操作不得小于 44px。
- 项目网格使用 12px 间距；卡片圆角使用 12px；普通控件圆角使用 8px；仅搜索框与胶囊状态允许全圆角。
- 工作区文本、表单和运营信息的有效内容最大宽度为 1240px；包含左右 104px 桌面边距的普通页面框架最大宽度为 1448px。
- 项目等以可视卡片扫描为主的集合页允许在 `>=1600px` 使用流式宽屏框架，但必须保留 104px 页面边距；卡片保持固定尺度，不得随视口无限拉宽。项目卡片桌面标准为 236×189px、12px 间距。
- 工作台页面必须显式选择布局类型：项目、画布、素材、技能使用 `collection`；任务记录使用 `data`；积分、团队、设置等高可读性信息页使用 `standard`。`collection` 与 `data` 在 `>=1600px` 使用 104px 固定边距，`standard` 继续遵循 1240px 有效内容宽度。
- 集合页卡片不得在超宽屏无限拉伸。画布卡片保持 240–260px，素材卡片保持 240–260px，技能卡片保持 272–292px；剩余空间保留为自然尾部留白，不通过放大卡片填满一行。
- 管理后台桌面端使用 236px 侧栏，并在剩余空间内遵循 1240px 内容宽度；小于 1280px 时切换为 56px 顶栏与 320px 左侧抽屉，避免侧栏挤压表单和宽表格，不得把全部后台导航压缩为横向滚动条。
- 管理后台页面框架最大宽度为 1304px（包含左右各 32px 内边距，对应 1240px 有效内容区）；禁止在超宽屏把表单、指标卡和运营表格无限拉宽。
- 管理后台导航按业务域固定分为核心概览、用户与增长、模型与成本、运营工具、系统设置；禁止使用“平台资源”“其他”等无法预测内容的宽泛分组。桌面与移动端均提供功能搜索，分组默认仅展开当前业务域，路由切换后自动展开目标分组。
- 管理后台依靠页面底色、白色内容表面、留白和分隔线建立层级；工具栏、表格、配置卡片不得同时叠加外框与阴影。配置区图标使用无底色的 16–20px 线性图标，禁止再套装饰性圆角方块。
- 管理后台抽屉统一使用 56px 标题栏、16px / 22px 标题和 24px 桌面内容边距；表单标签统一为 13px / 500，移动端再收敛到 16px 内容边距。
- 管理后台数据页统一采用“概览指标 → 条件筛选 → 数据表格”的纵向节奏：指标区只保留一层连续表面与弱分隔，搜索框占据剩余宽度，筛选控件使用一致列宽；1280px 以下必须自动收为单列，不允许工具栏挤压或横向溢出。
- 后台表格的模型名、业务主键等主信息使用 13px / 600，辅助标识使用 11px 等宽字体；空状态不再套装饰性图标容器，加载骨架必须尊重页面请求的行数，禁止人为填满首屏制造高密度假象。
- 管理后台编辑类 Modal、确认框和 Drawer 共用一套操作弹层规范：56px 标题栏、16px / 22px 标题、20px 桌面内容边距、底部独立操作区；取消在前、确认在后，危险确认仅对最终操作按钮使用错误色。
- 后台表单校验必须紧邻字段显示 12px / 17px 明确错误，错误字段使用语义错误色边界与焦点环；异步提交按钮必须展示 loading 并阻止重复提交。移动端弹窗保持 12px 视口边距，双按钮等宽且热区不低于 44px。
- 后台行操作菜单统一使用 180px 最小宽度、13px / 20px 菜单文字和 34px 桌面行高；普通操作使用中性文字，危险操作只在对应菜单项使用错误色，不允许整组操作同时高亮。
- 后台 `Popconfirm` 统一挂载 `admin-operation-popconfirm`：最大宽度 360px、14px / 20px 标题、12px / 18px 说明、单层边界与统一浮层阴影；按钮右对齐并保持 8px 间距。
- 后台表格与对象抽屉共用 `AdminTableEmpty`，抽屉和嵌套表格使用 `compact` 变体；只允许收缩高度，不允许退回 Ant Design 默认插画、默认文案或另一套色彩。
- 后台内容根节点与直接子级必须使用 `min-width: 0` 和 `max-width: 100%`；表格的横向溢出只能发生在 `.ant-table-content` / `.ant-table-body` 内部，不得撑宽页面或被页面静默裁切。
- 390px 至 1279px 的顶部栏、抽屉导航、筛选操作和普通表单控件使用不低于 44px 的触控热区；桌面紧凑表格操作可保留 32px 级别，但必须具备可见焦点和明确 `aria-label`。
- 后台配置页与对象抽屉统一使用 `AdminContentSkeleton`、`AdminTableEmpty`、`AdminContentError` 表达加载、空数据和失败；失败状态必须展示真实原因和原地重试，不得只弹 Toast 后落入空状态。
- 存储服务页分别维护 OSS 配置与历史迁移的加载、保留数据刷新和失败状态；配置加载失败时不渲染可编辑空表单，迁移状态失败时锁定迁移入口并保留原地重试。
- OSS 保存栏使用真实值比较表达“已同步 / 未保存”；历史迁移和失败项重试都使用不可绕过的确认短语，提交中锁定弹窗，并持续展示活动任务、发起人与开始时间。
- OSS 配置按“存储目标 / 访问凭据”分区，Endpoint、Bucket 与凭据错误紧邻字段；已保存密钥留空继续表示保留原值。
- 未保存 OSS 配置必须同时拦截浏览器刷新与后台内部导航；配置刷新保留本地草稿，迁移概览首次失败使用明确失败状态而不是“尚未执行”。
- 支付配置页在首次读取失败时只显示共享错误状态，不渲染默认空表单；微信与支付宝字段按后端支付协议分开映射，渠道专用密钥不得跨渠道展示。
- 支付表单使用规范化值比较驱动“已同步 / 未保存”，HTTP(S) 地址错误必须阻止提交；保存中锁定所有输入，敏感值继续使用“已配置、留空保留”的单一路径。
- 邮件服务页使用共享骨架和错误状态区分首次加载、失败与可编辑配置；SMTP 端口保持数值契约，启用时必需字段使用紧邻字段的阻断校验。
- 邮件配置以修剪后的真实值比较驱动“已同步 / 未保存”；已保存密码留空表示保留原值，保存期间锁定完整表单，未接入后端的测试邮件入口不得展示。
- 邮件服务存在未保存修改时必须同时拦截后台内部导航与浏览器刷新；校验失败不发送请求，保存期间保持表单锁定。
- 登录与注册页分别维护注册策略和 Linux.do OAuth 的加载、失败与可编辑状态；单个接口失败只影响所属区块，并保留原地重试入口。
- Linux.do 配置以修剪文本、去重排序 Scopes 后的真实差异驱动“已同步 / 未保存”；启用状态下必需字段与 HTTP(S) 地址使用字段级阻断校验，已保存密钥留空表示保留原值。
- 系统公告页使用共享骨架、错误和空状态区分首次加载、刷新失败与真实空列表；刷新失败保留上次成功数据时必须明确说明。
- 发布公告弹层展示全用户即时生效影响并保护未发布草稿，提交期间禁止关闭；关闭公告的确认信息必须包含公告标题且准确说明仅从用户端撤下、保留历史。
- 法律与协议页首次读取失败使用共享错误状态替代空编辑器；刷新失败保留旧文档时必须标注其事实来源。
- 富文本编辑器按真实同步基线计算脏状态，保存期间锁定编辑，未保存内容离开需确认；窄屏工具栏换行且触控热区不低于 44px。
- 用户详情等指标摘要使用单层连续表面与弱分隔，不允许为每个数字再套独立圆角边框；列设置等自定义浮层必须挂载后台语义类并复用统一阴影、文字和移动端 44px 行高。

## 按钮与工具栏

- 页面头部只放当前页面级操作，顺序为次要操作在前、创建或新增操作在后。
- 同一页面头部按钮统一为 36px 高、14px 字号、8px 圆角和中性表面，不通过蓝色区分同级操作。
- 蓝色仅保留给页面内容中的明确主操作、选中状态、进度和焦点，不用于制造多个竞争 CTA。
- 搜索、筛选、排序属于列表工具栏，默认放在标题下方；重置仅在筛选条件变化后出现。
- 390px 视口下，两个及以上头部按钮等宽排列；单个按钮保持内容宽度。按钮组允许换行，不使用隐藏横向滚动条掩盖溢出。

## 画布媒体节点编辑器

- 图片、视频和音频节点共用 `canvas-media-prompt-panel` 视觉契约；媒体类型只决定真实功能、参数和预览内容，不得分别维护面板、字体、模型选择器或提交按钮的视觉标准。
- 桌面编辑面板统一为 660px 宽、最小 192px 高、12px 圆角；顶部工具为 26px 高语义胶囊，底部控件为 32px 高、8px 圆角。
- 模型选择器在节点底部保持透明表面，通过图标、名称和下拉箭头表达操作；图片、视频、音频不得分别使用不同底色或描边。
- 输入正文统一为 13px / 20px / 400，工具和模型名称统一为 12px / 16px / 500，计费与字符数统一使用紧凑元数据层级。
- 参数入口、模型入口和提交按钮必须在同一基线上；分隔线仅用于模型、模式、参数等真实操作组边界。
- 首页与画布内的节点、Agent 输入框共用 `CanvasSubmitButton`：统一使用 32×32px 正圆热区、向上箭头、等待旋转和红色停止态；不因媒体类型或配置面板切换为其他圆角、胶囊或整行按钮，积分预估独立位于按钮左侧。
- 图片、视频和音频预览区域允许保留符合媒体语义的宽高比；视觉统一不等于强行统一内容比例。
- 画布可读文字不得低于紧凑元数据层级 11px；缩放值、节点状态、创建节点标签和角标不得通过 7–10px 字号压缩信息。

## 画布顶部栏

- 桌面画布顶部栏距顶部 20px，左侧项目身份区为 234×40px、12px 圆角；内部 Logo、项目名称与画布名称在同一基线，单项高度不超过 32px。
- 项目名称与画布名称使用 13px / 20px / 500，并通过截断控制宽度；禁止让长画布名称把顶部栏扩展成横跨页面的大胶囊。
- 工作模式保持独立表面；右侧分享、协作、积分与 Agent 按真实操作分组，不使用一个外层大胶囊包裹全部按钮。
- 夜间表面使用半透明 `#262626` 与 `#363636` 边界；日间使用半透明白色与 `#e5e7eb` 边界，尺寸和信息层级保持一致。
- 全站悬浮提示统一使用高对比深色表面、白色 12px / 18px / 600 文本、8px 圆角、1px 半透明亮边和轻量双层阴影；禁止使用与页面背景明度接近的灰底灰字。长文案最大宽度 280px，必须自然换行。
- 顶部栏右侧高频操作使用 40px 独立表面、12px 圆角与 8px 间距，顺序为协作、分享、积分、Agent；搜索和媒体性能属于低频工具，统一收纳在画布菜单，不与高频操作平铺堆叠。
- Agent 右侧面板使用不覆盖画布的停靠工作区，默认 400px，并允许在 320–560px 之间拖拽调整；面板尺寸变化只做 O(1) 视口补偿并保持当前世界中心。输入框保留附件、来自系统动态目录的图片/视频模型、公开 Skills 与显式执行模式入口，首页和画布共用同一草稿契约；选择结果只作为本次运行配置提交，由服务端校验、解析并冻结，禁止浏览器拼接 Skill 指令或建立本地 Skill 路由。过程区只展示服务端持久化事件、真实步骤、工具结果和审批状态，禁止定时器伪进度。审批卡展示冻结工具身份与参数，最终结果只有在服务端交付验收满足时标记为“交付已验收”。
- Agent 宿主切换固定为 `managed / local_codex` 两项单选组，用户文案为“网站 / 本机”，每项提供图标、Tooltip、`aria-label` 和 `aria-pressed`；不得根据连通性、历史或错误自动切换。两个工作区同时保留各自草稿与历史状态，但隐藏工作区不得继续发起新请求。
- 本机连接表单只接受 `http://127.0.0.1:<port>` 和会话 token，状态明确区分未连接、连接中、已连接与错误。连接成功后用紧凑工具栏提供本机历史、新建对话和断开；断开或取消失败时保留真实连接/turn 状态并展示 `role=alert`，不能先在视觉上伪装为已断开。
- 本机 Codex 生命周期、用户消息和最终回复属于本机历史；`canvas.read` 等工具活动、写入审批、媒体报价和权威结果仍复用网站 Runtime 组件。网站与本机内容不得混排为一条伪统一时间线，也不得用本机文案覆盖后端交付验收。
- Agent 时间线在 `running` 且尚无用户可见 `agent_message` 增量时，使用星形图标、流光“思考中”、展开箭头和真实事件轨迹；首个真实增量到达后自动收起为“已思考”，由 `itemId` 保持下方同一无标题正文增量增长。轨迹中的勾选、spinner、失败图标、工具与交付验收只投影服务端事实；不得渲染 `reasoning_content`、模拟思考步骤、伪造耗时或定时生成进度。
- Agent 工具活动按服务端 `itemId + sequence` 合并持久历史与实时事件，同一工具只保留一条生命周期记录。只读与 Skill 加载只展示事实，不显示审批；画布写入、资产发布和媒体生成共用单层审批卡，每卡仅一组“批准执行 / 拒绝执行”。媒体卡必须在同一表面展示冻结模型、参数、积分报价和有效期；过期或身份不匹配时用明确错误替代按钮，不允许继续提交旧提案。生成成功的图片、视频和音频直接展示真实资源预览，后续画布失败不得隐藏已经产出的媒体。退役 Stage、Specialist、Production Graph、Artifact Review 以及定时器假进度不得出现在当前界面。
- Agent 执行模式弹层固定使用紧凑事实文案与语义图标：“手动模式 / 手掌 / 每次生成前询问”和“自动模式 / 芯片 / 推理按 Token 计费，媒体生成前确认”；说明单行截断，不得使用循环箭头代表自动模式，也不得使用与真实审批行为不符的“完全自动生成”。
- Agent 结构化询问严格投影服务端 `waiting_input/pendingClarification/clarificationHistory`：状态文案使用“询问中”，当前卡停靠在消息过程与 composer 之间；单选、多选、自由文本、自定义答案、忽略、上一题/下一题及最终提交均保留结构化身份，不从问题文案推导交互。卡片最多一层圆角边框，编号选项用无边框弱背景表达选中，错误使用 `role=alert`、状态使用 `aria-live=polite`、问题使用 `fieldset/legend`。409 只刷新一次权威 Run 并要求用户核对，不自动重交；失败保留草稿，成功后只采用服务端 view。
- `<=639px` 时顶部高频操作和模式切换保持 44×44px 点击热区；可隐藏文字与积分，但不得把主要点击目标压缩到 32px。

## 画布右键菜单

- 空白画布右键菜单使用紧凑命令菜单，不展示重复的菜单标题、分组标题或装饰性图标容器。
- 桌面菜单统一为 196px 宽、16px 圆角、8px 内边距；菜单项统一为 32px 高、8px 圆角、13px / 20px / 400。
- 夜间表面使用 `#262626`，边界使用 `#363636`；阴影仅使用 `0 8px 32px rgba(0,0,0,.15)` 与 `0 2px 8px rgba(0,0,0,.1)` 两层轻阴影。
- 菜单结构只通过一条弱分隔线区分创建操作与历史/剪贴板操作；快捷键保持低对比度，不与命令名称争抢层级。
- 日间模式使用白色表面和 `#e5e7eb` 边界，并保持相同尺寸、字体和交互层级。
- “添加节点”二级面板与空白画布菜单共用 196px 宽度和单列命令结构；分组标题为 32px 高、12px / 16px / 500，命令行为 32px 高、图标 14px、文字 13px / 19.5px / 400，行间距 4px。
- 从空白画布菜单进入“添加节点”后，添加面板在原位置替换一级菜单，不允许两个菜单并排同时显示；内容需要滚动时保留滚轮与触控滚动能力，但不展示常驻滚动条轨道。
- 二级面板只展示系统真实支持的节点与资源入口，不为了复刻参考产品写入未实现的节点类型；独立工具栏创建器可按其场景保留宫格布局。
- 独立工具栏创建器与空白画布“添加节点”二级面板共用 196px 单列命令结构、分组标题、字体、图标、悬停状态与阴影；弹层与底部工具栏之间至少保留 16px 视觉间距。
- 两处添加节点面板保留滚轮、触控板和触摸滚动，但不展示常驻滚动条、轨道或上下箭头。

## 画布弹层系统

- 画布内 Modal、Popover、Dropdown、右键菜单和自绘浮层必须分别挂载 `canvas-overlay-modal`、`canvas-overlay-popover`、`canvas-overlay-dropdown`、`canvas-overlay-panel` 语义入口，不允许直接使用未映射的组件默认外观。
- 所有弹层共享 12px 外层圆角、8px 控件圆角、单层边界、克制阴影和同一套字体层级；业务组件只负责内容布局，不得重复定义外层表面、阴影和标题栏。
- Modal 标题使用 14px / 20px / 600，正文和控件使用 14px / 20px，辅助说明使用 12px / 17px；关闭按钮与图标操作热区不小于 32×32px。
- Popover 与 Dropdown 菜单项使用 13px / 20px，桌面最小高度 32px，移动端最小高度 44px；只保留纵向滚动能力并隐藏常驻滚动条。
- 新增弹层必须优先复用 `canvas-overlays.css` 的语义变量和现有 Overlay 组件；菜单的 196px 宽度只属于空白画布命令菜单，Popover、Modal 与 Drawer 依据内容契约选择尺寸。
- 只需要纵向滚动的弹层必须声明 `overflow-x: hidden`，并在验收时同时核对 `clientWidth` 与 `scrollWidth`，不允许遗留原生横向滚动条。

## 颜色与层级

- 页面、表面、次级表面、文本、分隔和交互色必须使用 `workspace-ui.css` 中的语义变量。
- 日间模式中承载真实说明、标签或元数据的 11–14px 文本，与页面或内容表面的对比度不得低于 4.5:1；低于该门槛的色阶只允许用于禁用态或纯装饰元素。
- 蓝色只用于主要操作、进度、焦点和明确可交互状态。
- 默认不使用渐变、纹理、重阴影或卡片套卡片。
- 层级优先通过留白、对齐、字体和明度差表达；边框仅在信息边界不清时使用。

## 页面结构

- 每页仅保留一个 `h1`。
- 标题、数量与主要操作放在同一条页面头部节奏中。
- 列表页优先选择与对象形态匹配的呈现：可视项目使用网格，运营记录使用表格。
- 搜索、筛选和排序必须保留真实功能；参考站不存在的后端功能不伪造。
- 管理后台列表首屏加载统一使用 `AdminTableSkeleton`，后台刷新保留现有数据并使用表格原生加载状态；分页统一通过 `PaginationBar` 或等价配置展示“当前范围 / 总数”。
- 桌面分页热区不得小于 32px，移动端不得小于 40px；固定页容量的列表必须隐藏页容量选择器。
- 设置卡中的直接表单统一使用 `admin-content-form`，由卡片提供唯一一层内容边距；内部 Grid 只负责列与间距，不重复添加 `px-* / pt-*`。
- 后台设置页统一复用 `SettingsSectionCard`、`AdminSettingsSwitchPanel` 与 `AdminSettingsSection`：页面只负责字段与业务状态，不得自行复制面板标题、状态栏、语义分区或保存栏结构。
- `AdminSettingsSection` 固定采用“左侧职责说明 + 右侧字段网格”，后台可用宽度不足时统一收为单列；新增设置页不得创建页面私有的平行表单框架。
- 可保存设置必须通过 `onValuesChange` 维护真实脏状态：无变更时禁用保存，有变更时显示明确状态，保存成功后复位；高级配置使用 `admin-form-disclosure` 渐进展示。
- 运维中心的升级、回滚、备份和环境校验共用一套受控操作模式：按钮必须提供禁用原因，活动任务必须展示阶段、发起人和日志入口，确认弹窗必须列出真实影响与精确确认短语。
- 运维任务执行期间禁止用 Toast 代替持久状态；页面内 `role=status` 区域持续反映控制器事实，冲突操作保持禁用直至后端返回完成态。
- 模型定价等高密度运营页首次请求失败时使用 `AdminContentError` 替换指标与表格，禁止以零值指标或空状态掩盖失败。
- 商业参数和模型定价抽屉通过 `onValuesChange` 维护真实脏状态；无变更时保存按钮禁用，保存成功后恢复同步状态，保存期间不允许关闭抽屉。
- 音色管理使用同一列表工具栏承载渠道、搜索、类型和状态筛选，并持续显示筛选结果数量；读取失败使用 `AdminContentError`，不降级为空表。
- 音色供应商同步使用独立 loading 状态并保留当前目录；编辑与克隆抽屉使用真实脏状态，未修改禁止保存，关闭未保存内容前必须确认。
- AI 模型配置的渠道列表和渠道模型列表分别使用 `AdminContentError`、共享表格骨架和共享空状态；有旧数据的刷新失败保留列表并展示可重试错误。
- 渠道及模型抽屉通过 `onValuesChange` 维护真实脏状态；无变更禁止保存，保存或图标写入期间禁止关闭，切换到新增模型前保护未保存内容。
- 模型管理页头不再使用页面私有 Tailwind 边框堆叠，统一使用后台标题、说明、操作区、筛选结果计数与响应式按钮规则。
- 积分运营页的策略表单使用 `onValuesChange` 维护真实同步状态；首次读取失败以 `AdminContentError` 替代表单，无修改时保存按钮禁用。
- 人工调账提交前使用后台统一确认浮层展示用户、带正负号的积分变化和调整依据；负向调整仅在最终确认按钮使用危险色。
- 异常计费首屏使用共享表格骨架，失败保留真实原因和重试入口；已有订单刷新失败继续展示原数据，结算写入期间弹窗不可关闭。
- 积分策略与人工调账的双栏布局只在视口至少 1280px 时启用；后台侧栏存在时，1024px 级视口必须保持单列，禁止用通用 `xl` 类提前触发并被主容器裁切。
- 运行策略等超长配置页必须提供清晰的页内分区导航；首次读取失败使用明确错误与重试入口，固定保存区不得覆盖最后一组字段，移动端分区入口热区不低于 44px。
- 请求日志必须把筛选结果总量与当前页成功/失败明确区分；首次加载失败替代表格，已有日志刷新失败继续保留数据，长模型和错误字段只允许在表格内部横向滚动。
- 分镜提示词管理必须明确展示当前启用版本、未启用版本和可用变量；首次加载失败不得伪装为空列表，已有数据刷新失败时保留当前版本目录并提供原地重试。
- 分镜提示词抽屉必须以真实脏状态控制保存与关闭；变量插入视为内容修改，无变更禁止重复保存，保存期间禁止关闭或重复提交。
- 邀请奖励运营页必须把活动总开关、套餐双边奖励和邀请关系分区呈现；首次读取失败不得渲染伪造指标，刷新失败保留已有数据并提供重试。
- 套餐奖励规则使用真实脏状态控制逐行保存，无修改显示已同步；取消奖励资格必须展示目标用户和邀请码，提交期间禁止关闭确认弹窗。
- 站点与品牌页必须将品牌、首页横幅、页脚版权和备案信息按公开页面职责分区，并提供可键盘访问的页内导航。
- 站点配置首次读取失败时禁止渲染空白可编辑表单；表单脏状态必须基于与服务端同步值的真实比较，Logo 写入与配置保存不得并发覆盖。
- 兑换码批次列表和批次明细分别使用共享表格骨架、持久错误与共享空状态；已有数据刷新失败继续展示上次成功结果，创建成功后重新读取服务端分页事实。
- 批次和单码禁用必须在确认区显示实际影响并阻止重复写入；生成结果弹窗在移动端保持 44px 操作热区，复制、下载与明细表格不得造成页面级横向溢出。
- 用户管理使用共享列表工具栏、表格骨架、持久错误和空状态；首次失败替代表格，刷新失败保留当前目录并提供原地重试。
- 用户编辑抽屉按规范化后的账号值比较真实脏状态；角色或启停状态变化必须在提交前列出目标用户与实际差异，无变化时禁用保存。

## 响应式断点

- 390px：移动工作区，16px 页面边距，44px 触控控件，卡片单列。
- 768px：平板窄屏，保持完整操作文案，工具栏允许分行。
- 1024px：桌面起始布局，页面左右边距 104px，标题与操作优先同排。
- 1440px：完整桌面布局，内容区保持最大 1240px，不随浏览器无限拉宽。
- 1600px 及以上：普通信息页继续遵循 1240px 内容宽度；项目集合页切换为 104px 固定边距的流式画布，避免形成居中的窄内容岛。

## 可访问性与动效

- 所有操作使用原生按钮、链接或可聚焦表单控件。
- 仅图标操作必须提供 `aria-label`。
- 焦点使用语义焦点色，并保持至少 2px 可见轮廓。
- 动效只表达悬停、聚焦和状态变化，并遵循 `prefers-reduced-motion`。
