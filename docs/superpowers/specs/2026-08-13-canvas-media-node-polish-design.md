# 画布媒体节点克制融合设计

## 目标

在现有统一节点体系上提升图片、视频与音频节点的完成度。吸收参考产品在比例、留白、信息层级和弱选中态上的优点，但不复制品牌资产、未实现能力或虚假状态。

本设计是 `2026-08-13-canvas-node-ui-standard-design.md` 的定向视觉升级，并明确覆盖其中“媒体默认尺寸不调整”和“沿用强蓝色选中态”两项决定；其余共享节点契约继续有效。

## 已选择方案

采用“克制融合版”：

- 保留 HMaigc 当前主题、功能入口、模型能力、参数和生成流程。
- 参考成熟创作工具的宽幅媒体布局、标题外置、扁平表面与低干扰焦点反馈。
- 图片、视频、音频使用同一媒体节点视觉骨架，内容比例继续由真实媒体语义决定。

未选择的方案：

1. **一比一复制参考站**：会引入不属于本产品的品牌语言、能力暗示和交互细节。
2. **只改颜色和阴影**：无法解决预览区与提示词区宽度失衡、身份层级不清和空态松散等根因。

## 当前问题

1. 媒体预览节点与下方提示词面板宽度差异过大，两个区域像临时拼接。
2. 高饱和蓝紫描边在空节点和多节点场景中抢占注意力，更像调试状态。
3. 节点身份藏在预览内部中央，标题、内容与状态的层级不稳定。
4. 18px 圆角、常驻重阴影和多层表面叠加，使画布显得厚重。
5. 空态只有小图标与短文案，大面积空间没有形成清晰的操作暗示。

## 视觉结构

### 1. 媒体节点组

每个媒体节点在视觉上由两个同宽区块组成：

1. **身份与预览区**：标题位于预览外部上方；预览内部只展示媒体、真实状态或空态。
2. **提示词与操作区**：沿用已统一的媒体提示词面板，左右边缘与预览区对齐。

两个区块之间使用 12px 间距，不增加第三层包裹卡片，不使用连接线或装饰底板把它们圈在一起。

### 2. 尺寸

- 桌面媒体节点标准宽度为 620px。
- 提示词面板与预览区同宽，不再固定为与节点无关的 660px。
- 视频预览保持 16:9；图片预览保持模型输出或资源真实比例；音频使用同宽紧凑播放器结构。
- 新建媒体节点直接采用新标准尺寸。
- 已有节点若仍是系统旧默认尺寸，则在加载时归一为新标准；用户明确调整过的自定义尺寸必须保留，不得强制覆盖。
- 节点尺寸归一必须同步 React Flow 的真实测量和连接点位置，禁止只用 CSS 放大造成命中区域与视觉区域错位。

### 3. 标题与身份

- 标题位于预览区上方，使用 `13px / 20px / 500`。
- 标题只展示真实节点类型或用户名称；版本、锁定、批次等事实按需紧邻展示。
- 预览内部不再重复显示“空视频节点”等身份标题；空态只说明当前内容状态与可执行动作。

### 4. 表面、边界与圆角

- 节点与提示词面板使用同一 `theme.node.fill` 表面和 `theme.node.stroke` 边界。
- 外层圆角统一为 12px，内部控件圆角统一为 8px。
- 默认状态无阴影；悬停或拖拽时只使用既有轻量 `shadow-sm` 语义。
- 删除媒体节点私有渐变、发光、重投影和双层描边。

### 5. 选中与交互状态

- 默认边界为中性弱边界。
- 选中时提高边界明度并混入约 25% 品牌焦点色，禁止整圈高饱和蓝紫描边。
- 选中不能只靠颜色表达：连接点、工具栏和焦点轮廓继续提供状态证据。
- 生成中、失败、取消、锁定等状态继续使用真实语义色，不因视觉优化被弱化或隐藏。

### 6. 空态

- 空态图标使用 40–48px 视觉尺寸，但不增加装饰性圆角图标卡。
- 主文案描述真实状态，例如“尚未生成视频”。
- 辅助文案只说明真实可执行入口，例如“输入提示词后开始生成”或“连接参考素材”。
- 不展示参考站的“尝试”能力清单，除非系统确实提供对应操作。

## 组件边界

本次最多包含三个生产职责：

1. **媒体节点布局契约**：统一标准宽度、标题位置、预览与提示词区对齐。
2. **共享媒体状态表现**：统一空态、选中态、悬停态和表面层级。
3. **节点家族接线**：图片、视频、音频消费同一契约，保留各自真实预览与参数能力。

不得创建第二套节点渲染器，不得复制三个媒体节点组件，也不得修改生成、计费、资源、连接或后端契约。

## 变更预算

- 生产职责：不超过 3 个。
- 生产文件：目标不超过 8 个。
- 净新增生产代码：目标不超过 500 行。
- 不新增依赖、不修改数据库、不增加后端接口。
- 若必须覆盖超过 12 个生产文件或净新增超过 750 行，停止实施并重新评估边界。

## 性能与数据安全

- 不在拖拽、缩放、选择和视口移动热路径增加数组扫描、测量循环、持久化或网络请求。
- 旧默认尺寸识别必须是确定性的结构比较，不使用语义推断，也不覆盖用户自定义尺寸。
- 视觉归一不修改任务、积分、素材 URL、模型配置和节点业务数据。
- 视口交互期间继续关闭阴影和非必要动画。

## 响应式与可访问性

- 620px 是桌面标准宽度；窄视口按可用画布空间等比缩放，不产生页面横向滚动。
- 原生按钮、`aria-label`、可见焦点和键盘操作保持有效。
- 空态、选中、失败、生成和锁定均不能只依赖颜色表达。
- 动效遵循 `prefers-reduced-motion`。

## 验收标准

### 自动化

- 共享媒体布局契约覆盖图片、视频、音频三类节点。
- 验证新建节点使用标准尺寸，旧默认尺寸可归一，自定义尺寸不被覆盖。
- 验证提示词面板与预览区使用同一宽度和表面语义。
- 验证默认、悬停、选中、空态、生成、失败和锁定状态。
- Web 全量测试、TypeScript、Vite 构建、bundle budget 与 `git diff --check` 全部通过。

### 真实画布

- 在当前真实画布检查图片、视频、音频节点的空态与已有素材状态。
- 检查预览区与提示词区左右对齐，标题不重复，参数入口和生成按钮保持可用。
- 检查明暗主题、选中、悬停、拖拽、缩放、连接点和节点工具栏。
- 检查旧默认尺寸节点与用户自定义尺寸节点的归一边界。
- 重新构建本地镜像，Web 与后端健康，当前画布入口返回 200。

## 提交策略

视觉升级以独立 Conventional Commit 提交，不混入 `.superpowers/`、构建产物、本地数据、密钥或无关改动；不执行 push。
