# 画布节点 UI 统一设计

## 目标

以当前画布正在使用的节点视觉为唯一母版，统一所有节点的外壳、内部信息层级与状态表达。不得另起视觉体系，不得改变节点业务数据、生成流程、连接行为和媒体比例。

## 设计原则

1. **沿用现状**：继续使用当前深色节点表面、蓝色选中态、现有字体、画布主题 token 和交互语言。
2. **单一标准**：公共颜色、圆角、边界、阴影、标题、状态、元数据和操作只能由共享节点契约提供，节点私有组件不得重新定义外壳视觉。
3. **内容差异不是视觉分叉**：图片、视频、音频保留真实预览形态；文本、脚本和配置保留各自编辑内容，但都进入同一信息结构。
4. **显式失败**：加载、失败、取消、锁定和资源未就绪继续展示真实状态，不增加默认值、静默降级或假数据。
5. **不引入兼容层**：直接把现有节点切换到统一契约，不保留旧样式分支。

## 范围

### 纳入统一的节点类型

- 图片节点
- 视频节点（含视频合成节点）
- 音频节点
- 文本节点
- 分镜脚本节点
- 配置节点
- 技能节点
- 角色、故事输入、风格板等基于现有节点类型的自定义内容
- Frame 节点的标签与交互状态；Frame 继续作为空间容器，不强制改成内容卡片

### 不在本次修改范围

- 节点默认尺寸与媒体宽高比
- 节点生成、计费、资源加载和任务状态机
- 连接点语义、连线规则、拖拽与缩放逻辑
- 节点数据结构、后端接口与数据库
- 画布工具栏、右键菜单和非节点弹窗的整体重设计

## 统一结构

### 1. 公共外壳

所有内容节点继续复用现有 `CanvasNode` 与 `canvas-node-shell`，并统一：

- 外层圆角与单层边界
- 默认、悬停、选中、关联、生成中和失败状态
- 连接点、缩放点和焦点环
- 阴影强度与动效时长
- 明暗主题语义 token

媒体铺满节点时允许内容贴边，但边界与选中态仍由公共外壳绘制，不允许媒体组件再画第二层圆角边框。

### 2. 公共信息层级

所有节点采用同一语义顺序：

1. **身份层**：节点类型或业务标题、版本/锁定/批次等状态。
2. **内容层**：媒体预览、文本正文、脚本编辑器或配置内容。
3. **事实层**：模型、清晰度、时长、尺寸、字数、镜头数、资源状态等真实元数据。
4. **操作层**：编辑、替换、详情、取消、重试等真实操作。

节点没有某层事实时直接不渲染该层，不使用占位文字填充结构。

### 3. 节点家族差异

- **图片 / 视频**：预览继续铺满内容区；标题、状态采用一致的轻量覆盖层；事实和操作位于统一底部区域。
- **音频**：标题不再悬在公共外壳之外；空态、播放器、事实和操作使用同一节点结构。
- **文本 / 技能 / 配置**：统一标题、正文、元数据与操作的字号和间距，不改变内容编辑行为。
- **分镜脚本及复杂编辑节点**：外壳和头尾信息统一，内部专业编辑器不拆解或重写。
- **Frame**：只统一名称标签、选中态、连接/缩放反馈；空间容器本体保持低干扰。

## 统一状态

以下状态由共享表现层负责，所有节点使用相同图标、字号、间距和操作热区：

- 空节点
- 加载资源
- 排队与生成中（阶段、进度、耗时、任务号、详情、取消）
- 失败（真实错误、重试或修改提示）
- 已完成
- 已取消
- 锁定
- 版本与批次
- 资源存储状态

颜色仅表达语义：蓝色用于选中、焦点、进度和主操作；红色用于真实失败和危险操作；普通状态使用中性色。

## 组件边界

本次只允许三个生产职责：

1. **共享节点视觉契约**：集中定义节点结构 class、主题映射和状态样式。
2. **公共节点结构组件**：把重复的标题、事实栏、操作和状态内容收敛为小型可组合组件。
3. **节点家族接线**：图片、视频、音频、文本、脚本、配置和 Frame 消费上述公共契约。

不得创建第二个节点渲染系统，也不得把所有节点业务内容塞进一个超长配置对象。

## 变更预算

- 生产职责：不超过 3 个
- 生产文件：目标不超过 8 个
- 净新增生产代码：目标不超过 600 行
- 新生产文件：单文件不得超过 500 行

若实际实现超过任一预算 50%，停止继续修改并重新评估模块边界，不允许边做边扩大。

## 性能约束

- 不改变拖拽热路径，不在 `onNodesChange`、拖拽或缩放过程中增加数组扫描、序列化或网络请求。
- 公共视觉派生只依赖单节点类型、状态和主题，不订阅完整 nodes/edges 集合。
- 视口交互期间继续关闭昂贵阴影和动画。
- 媒体资源加载策略保持不变。

## 可访问性

- 所有操作继续使用原生按钮。
- 图标按钮必须有 `aria-label`。
- 选中、生成、失败和锁定不能只靠颜色表达。
- 焦点可见，操作热区维持现有画布规范。
- 动效遵循 `prefers-reduced-motion`。

## 验收标准

### 自动化

- 为共享节点结构增加契约测试，覆盖所有 `CanvasNodeType`。
- 覆盖空态、加载、生成、失败、完成和锁定状态。
- 覆盖图片、视频、音频、文本、脚本、配置和 Frame 的专属内容仍可渲染。
- 运行 Web 全量测试、TypeScript 构建、Vite 构建和 bundle budget。
- `git diff --check` 通过。

### 真实页面

- 在当前画布分别检查图片、视频、音频、文本、脚本、配置和 Frame。
- 检查明暗主题、选中、悬停、生成、失败、空态和缩放后的可读性。
- 确认节点内部没有第二层无职责的圆角边框。
- 确认拖拽、缩放、连接和生成操作没有行为回归。
- 完成后重新构建本地镜像，Web 与后端健康检查通过，当前画布入口返回 200。

## 提交策略

以一个职责单一的 Conventional Commit 提交节点 UI 统一改动。提交不得包含视觉伴侣文件、构建产物、密钥、本地数据或无关格式化变更；不执行 push。
