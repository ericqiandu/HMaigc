# 账号级 AI 水印与规范发布设计

## 背景与目标

当前水印配置同时存在浏览器本地默认值、视频节点元数据和 provider 参数映射，多处事实源会导致跨设备设置不一致、任务重试漂移，也无法证明用户同意了哪一版去水印规范。

本设计将水印能力硬切为账号级单一事实源：管理员在“法律与协议”发布 AI 水印规范，用户阅读当前版本后可为账号开启“去 AI 水印”，后端在创建生成任务时冻结真实水印指令。图片和视频节点不再展示或提交水印参数。

质量目标是可审计、可跨设备同步、任务可复现，并对不支持水印控制的模型如实披露。禁止保留本地与节点级兼容路径，禁止自动换模型或伪造去水印结果。

## 已确认的产品规则

- 新账号与现有账号默认关闭“去 AI 水印”，即新任务优先请求生成带水印内容。
- 管理员未发布有效的 AI 水印规范时，用户不能开启去水印。
- 开启并保存“去 AI 水印”即代表账号主体阅读并同意当前规范版本，不再增加重复确认框。
- 每个规范版本由两项共同组成：后台可编辑的“AI 生成内容水印管理规则”正文，以及单独填写的“水印规范”外链；二者都必须发布后才能开放去水印。
- 水印规范外链只接受无账号密码、无 fragment 的 HTTPS URL，系统不抓取、不缓存也不判断外链正文。
- 管理员可在内容或 URL 不变时显式重新发布新版本，用于外部正文变化等场景；必须二次确认该操作会令旧同意失效。
- 发布新版本后，旧同意自然失效。旧偏好不批量覆盖，但其有效状态变为关闭，用户必须重新确认。
- 账号设置只影响新任务。任务创建后，排队、执行与重试均使用创建时冻结的水印事实。
- 支持水印控制的模型按账号事实显式发送 `watermark=true/false`；不支持的模型不发送该字段，并在界面明确说明结果由模型服务商决定。

## 领域模型

### PolicyPublication

`PolicyPublication` 是不可变的规范发布事实，而不是可覆盖的站点配置正文。

字段至少包括：

- `id`
- `kind`，本期只允许 `ai_watermark`
- `version`，同一 kind 从 1 单调递增
- `managementRuleRichText`，AI 生成内容水印管理规则正文
- `watermarkPolicyURL`，水印规范 HTTPS 外链
- `contentHash`，对管理规则正文与外链生成稳定摘要
- `publishedBy`
- `publishedAt`

数据库对 `(kind, version)` 建立唯一约束。发布使用数据库事务串行计算下一版本；并发发布冲突显式返回，禁止覆盖已发布版本。管理规则正文沿用现有法律富文本白名单和长度限制；外链不进入服务端抓取链路。正文或外链任一为空时均不构成可用 publication。

### UserWatermarkPreference

每个账号唯一一条当前偏好：

- `userId`
- `removeWatermark`
- `acceptedPublicationId`
- `acceptedAt`
- `createdAt`
- `updatedAt`

不存在记录等同于 `removeWatermark=false`。关闭去水印不删除历史同意记录；当前偏好可保留最后一次 publication 引用以解释失效原因，但任何有效性判断必须与当前发布版本实时比对。

### UserPolicyConsent

`UserPolicyConsent` 保存不可变同意历史：

- `id`
- `userId`
- `policyPublicationId`
- `acceptedAt`

对 `(userId, policyPublicationId)` 建唯一约束，使重复保存幂等。规范正文、外链、版本和发布者均通过不可变 publication 追溯，禁止在 consent 表复制一份可漂移正文。

### 账号有效状态

账号的有效状态由后端统一计算：

- `disabled`：用户明确关闭或从未设置。
- `active`：用户开启，且 accepted publication 等于当前 publication。
- `policy_updated`：用户曾开启，但当前 publication 已更新。
- `policy_unavailable`：当前没有可用规范。

前端不得自行用版本号推断状态。后端返回状态、当前规范摘要和可操作性，前端只负责展示与提交用户选择。

## 协议发布

后台“法律与协议”保留现有用户协议、隐私政策和会员服务协议，在同一页面新增第四项“AI 水印管理规则”。其保存动作和版本状态独立，不与现有三份正文组成一次联合更新。

该项同时提供两个必填字段：

- `AI 生成内容水印管理规则`：复用现有法律富文本编辑器，承载产品说明、责任边界和账号设置规则。
- `水印规范外链`：单独的 HTTPS URL 输入框，用于链接更详细的外部水印规范；后台预览和账号弹窗均以新窗口打开并使用 `noopener noreferrer`。

“发布新版本”每次都把正文与外链作为一个不可分割的 publication 插入。正文或 URL 未变化时允许重新发布，但提交前必须提示“当前内容未变化，继续发布会要求所有已开启账号重新确认”。发布成功后显示版本、发布时间和发布管理员，并写入管理员审计事件；审计只保存 publication ID、版本和摘要，不复制完整富文本。

未发布规范时不会阻止普通带水印生成，只阻止开启去水印。规范读取或发布失败必须显示真实错误；不得渲染默认正文或伪造已发布状态。

## 账号交互

头像菜单保留“AI 水印设置”。点击后直接打开居中弹窗，不再跳转到独立水印设置页面。弹窗只参考用户提供截图的布局、层级、间距和交互，不复制第三方品牌名称、文案或链接。

弹窗包含：

- 标题“AI 生成内容水印管理规则”；
- 后台发布的管理规则富文本正文，正文直接铺陈，不增加多层卡片；
- 蓝绿色“水印规范”外链，新窗口打开；
- “去 AI 水印”开关；
- 开启说明“开启并保存即代表阅读并同意当前版本管理规则与水印规范”；
- 当前版本或失效状态提示；
- “保存设置”按钮。

视觉与可访问性约束：

- 深色大尺寸居中弹窗，使用轻遮罩和项目现有 Design tokens；独立 block 最多一层可见圆角边框。
- 正文保持紧凑行距与清晰层级，链接使用项目强调色；开关区域使用弱分隔，不再嵌套圆角卡片。
- 保存按钮位于右下角；右上角提供关闭按钮，并支持 Escape 关闭和键盘焦点闭环。
- 小屏宽度自适应且正文区域可滚动，开关和保存操作始终可达；禁止正文溢出遮挡操作。

交互规则：

- 当前规范未发布或首次读取失败时，开关与保存按钮禁用。
- `policy_updated` 显示“水印规范已更新，请重新阅读并确认”，视觉上按关闭处理。
- 开启并保存时提交用户所看到的 `publicationId`；后端在事务内再次核对当前版本。
- 管理员在用户保存期间发布新版本时，后端返回版本冲突，前端重新读取并要求用户确认，不记录旧版同意。
- 关闭不要求规范存在，但仍通过账号 API 保存并跨设备同步。
- 保存期间锁定控件。保存失败保留当前草稿选择并显示错误，不显示成功态。
- 不支持水印控制的已选模型在模型选择/参数说明中显示“该模型不支持水印控制，结果由模型服务商决定”，但不自动换模型。

## API 契约

### 账号 API

新增账号鉴权接口：

- `GET /api/me/watermark-preference`
- `PUT /api/me/watermark-preference`

GET 返回后端计算后的状态、当前偏好、当前 publication 摘要和可操作性。PUT 输入仅包含 `removeWatermark` 与可空 `publicationId`：开启时 publication 必填，关闭时忽略该字段。

开启事务必须同时：

1. 锁定当前 AI 水印 publication 事实；
2. 核对输入 publication 仍为当前版本；
3. 幂等写入 `UserPolicyConsent`；
4. 更新 `UserWatermarkPreference`。

关闭只更新 preference，不删除 consent。接口不得接受客户端传入规范版本、同意时间或有效状态。

### 管理员 API

新增独立接口：

- `GET /api/admin/legal/ai-watermark-policy`
- `POST /api/admin/legal/ai-watermark-policy/publications`

发布输入为 `{ managementRuleRichText: string, watermarkPolicyUrl: string }`。两项均必填；正文使用富文本安全校验，外链使用严格 HTTPS 校验。未知字段原地拒绝。管理员权限、严格 JSON、请求大小限制和审计沿用现有商业后台门槛。

### 规范展示

管理规则正文只在账号水印设置弹窗和后台预览中渲染，不新增平行站内协议页面。水印规范外链不做服务端代理或重定向；账号 API 直接返回经过验证的 URL 供前端新窗口打开。

## 生成链路

### 单一决策入口

客户端创建图片或视频任务时不再提交任何水印字段。后端在计费预留与任务创建的同一业务入口，根据账号有效状态和模型能力生成 `WatermarkDirective`：

- 账号 active 且模型支持：`without_watermark`，provider 参数为 `false`。
- 账号非 active 且模型支持：`with_watermark`，provider 参数为 `true`。
- 模型不支持：`provider_default`，provider 请求省略水印字段。

模型是否支持水印必须来自后端 adapter registry 的显式 capability，并安全投影到公共模型目录。禁止按模型名称、供应商字符串或前端硬编码推断。

### 任务冻结事实

任务创建时冻结：

- directive mode；
- provider 是否应用水印参数及其布尔值；
- 当去水印生效时使用的 publication ID 和版本；
- capability registry 的模型身份。

这些字段属于服务端任务事实，不从旧节点 metadata 恢复。任务执行、重新领取和原任务重试只读取冻结事实；用户随后关闭、重新开启或规范发布新版均不修改已有任务。

新建重试任务视为新请求，重新读取当前账号状态；同一任务的内部重试保持原快照。任务详情和结构化日志可显示 directive 与 publication 版本，但不得记录完整规范正文或敏感 provider 请求。

### Provider 映射

各图片/视频 adapter 只消费统一 directive，不读取用户偏好：

- capability 支持时必须显式映射 `true/false`；
- capability 不支持时必须确认请求体中不存在水印字段；
- 上游拒绝水印参数时按 provider 错误显式失败，不自动省略参数重试；
- 上游返回内容是否实际带水印不可由系统伪造判定，界面只陈述已提交的请求事实。

Seedream 5.0 Lite/Pro 不再固定 `watermark=false`，统一遵循本设计的账号级 directive。

## 旧逻辑硬切与迁移

必须删除：

- Zustand/local storage 中的 `videoWatermark`；
- 独立 `/settings?section=watermark` 页面状态；
- 图片、视频节点级水印开关；
- `node.metadata.watermark` 的编辑、优先级与生成输入映射；
- assistant/canvas plan 接受客户端 watermark 字段的能力；
- “节点优先、全局兜底”的全部分支。

历史节点 metadata 可继续作为不可解释的旧 JSON 留存，但生产代码不读取、不迁移、不回写；禁止为其增加兼容层。历史已创建任务不反向改写。

数据库仅执行增量建表和索引迁移，不删除、不覆盖用户、任务、资产或支付数据。迁移不会根据旧浏览器 local storage 推断账号偏好；所有账号以安全默认 `removeWatermark=false` 开始。

## 安全、审计与可观测性

- 外链必须为 HTTPS，禁止 username/password、控制字符和超长 URL；系统不发起服务端网络请求，避免 SSRF。
- 富文本继续使用现有白名单净化和安全链接规则。
- 用户同意记录、偏好更新、规范发布和失败均使用结构化事件；不得记录完整富文本、cookie、provider Key 或生成 prompt。
- 管理员发布与账号开启分别在单一事务内完成；唯一约束保证重复请求不会制造多份等价同意。
- 任务日志记录 directive、模型能力、publication ID/version 和 provider 参数是否应用，用于定位“为何出现/未出现水印”。
- publication 或账号偏好缺失时必须显式收敛为带水印，并向用户陈述真实原因。只有 registry 明确声明“不支持水印控制”的模型才允许 `provider_default`；模型 capability 缺失属于发布配置错误，必须阻止任务并显式失败，不得把“未知”伪装成“不支持”或已去水印。

## 测试与验收

### 后端

- 管理规则正文与水印规范外链共同发布、任一缺失拒绝、富文本安全、HTTPS 校验、版本单调递增、相同内容重新发布与并发冲突。
- 账号默认关闭、开启、关闭、重复保存、规范未发布、规范更新、保存时版本竞争。
- consent 不可变、唯一约束和 preference/consent 同事务回滚。
- 支持水印模型的 `true/false` 精确请求，不支持模型严格省略字段。
- 图片和视频至少各覆盖一个支持模型；覆盖现有拒绝水印参数的模型为不支持能力。
- 任务冻结后更改账号设置或发布新版，执行与内部重试仍使用旧快照。
- 新建任务使用新状态，旧节点 metadata 不影响请求。
- 权限、审计、日志脱敏和严格 JSON。

### 前端

- 头像菜单打开弹窗，不跳转旧页面。
- 未发布、加载失败、active、disabled、policy_updated 和保存冲突状态。
- 管理规则正文安全渲染，水印规范外链正确打开且包含安全属性。
- 弹窗在桌面与小屏保持正文可滚动、焦点闭环、Escape/关闭按钮可用且保存操作可达。
- 保存锁、失败保留草稿、成功后跨查询同步。
- 图片与视频节点均不存在水印开关，生成请求也不包含 watermark。
- 动态 capability 对不支持模型显示真实说明。

### 最终门禁

- Go focused tests、全量测试、race、vet、build。
- Web focused tests、全量测试、TypeScript/Vite build、格式与 bundle budget。
- 隔离 PostgreSQL 验证迁移、唯一约束、发布并发与用户同意事务；测试结束必须清理隔离容器和卷，禁止切换本地演示数据库。
- 真实浏览器覆盖账号弹窗、管理规则正文、外链规范、版本失效与图片/视频节点无开关。
- 最终 review 对照本规格、实际 diff、前后端 DTO、数据库迁移、Seedream 规格修订和任务冻结事实逐项核验。

## 变更预算与暂缓项

生产职责限定为三项：规范发布、账号偏好、生成链路注入。

- 预计生产文件 14–20 个。
- 预计净新增生产代码约 700–1100 行，同时删除旧本地与节点级逻辑。
- 若生产文件超过 30 个、净新增超过 1650 行或出现超过 500 行的新生产文件，停止实现并重新拆分，不继续堆补丁。

本期明确暂缓：

- 抓取、缓存或校验外链正文；
- 批量替用户开启去水印；
- 根据生成结果做视觉水印检测；
- 不支持模型的自动替换或降级；
- 历史任务和历史节点的反向改写；
- 独立法律草稿、审批流或定时发布系统。
