# Agent 服务端会话历史与恢复设计

## 1. 目标

在现有单一 Agent Runtime 上增加服务端会话历史与恢复能力，使同一用户能够在当前画布内查看最近对话、恢复最新运行，并在不同浏览器或设备上继续工作。

本阶段参考 ViMax Agent Loop 的会话复用能力：Web 与交互入口共享同一运行时、会话和工具事实，支持新建与恢复会话。参考只用于校准能力边界，不复制 ViMax 的固定创作流水线或代码结构。HMAigc 仍以现有多租户、画布权限、审批、计费和资产事实为实现真源。

## 2. 当前事实

- 服务端已有 `AgentThread`、`AgentRun`、`AgentCheckpoint` 和事件流，运行事实可以持久化并恢复。
- 所有运行均绑定用户、租户、领域项目和画布作用域。
- Web 当前只在浏览器本地保存当前画布最后一个恢复句柄。
- 本地句柄丢失或用户更换设备后，Web 无法发现服务端已有对话。
- 当前没有按画布列出 Agent 对话的公共接口。

## 3. 范围

### 本阶段完成

1. 服务端按当前用户和画布列出最近对话。
2. 每个对话返回其最新一次运行的完整可恢复视图；尚无运行的空对话显式返回 `latestRun: null`。
3. Web 在 Agent 面板展示最近对话，并允许选择和恢复。
4. 本地恢复句柄继续作为快速启动缓存，服务端历史列表作为权威发现来源。
5. 跨设备没有本地句柄时，自动选择服务端最近更新的对话。
6. 新建对话后刷新历史列表。

### 明确暂缓

- 对话删除、归档、重命名和搜索。
- 单个对话内所有历史 Run 的完整 transcript。
- 多 Agent、子 Agent 协作和 Agent 自我进化审批。
- 新增数据库字段或迁移。
- 从 ViMax 复制固定 Idea2Video、Script2Video 或 Novel2Video 流水线。

## 4. 方案比较

### 方案 A：服务端聚合对话与最新运行（采用）

单个接口返回当前画布最近对话及每个对话的最新运行视图。服务端负责作用域过滤、排序和有界聚合，Web 只解析并展示事实。

优点：单次请求、跨设备可恢复、权限边界集中、没有 N+1 请求。缺点：需要新增专用只读投影。

### 方案 B：只列 Thread，Web 逐个读取最新 Run

实现表面简单，但会产生 N+1 网络请求，列表状态难以保持一致，且前端承担了不属于它的聚合职责，因此不采用。

### 方案 C：直接实现完整 transcript

会同时引入 Run 分页、消息投影、搜索、归档和上下文压缩展示，超出当前里程碑，不采用。

## 5. 公共契约

新增只读接口：

```http
GET /api/agent/threads?canvasId=<canvas-id>&limit=<1..20>
```

响应数据：

```json
{
  "items": [
    {
      "thread": {
        "id": "thread-id",
        "canvasId": "canvas-id",
        "status": "active",
        "createdAt": "ISO-8601",
        "updatedAt": "ISO-8601"
      },
      "activityAt": "ISO-8601",
      "latestRun": {
        "run": {},
        "state": {}
      }
    }
  ]
}
```

约束：

- `canvasId` 必填，必须通过现有画布授权服务确认用户可访问。
- `limit` 缺省为 20，只允许 1–20；非法值返回明确的 400。
- 结果只包含登录用户本人在该租户、项目和画布作用域内创建的对话。
- `activityAt` 是只读派生事实：有运行时取最新 Run 的 `updatedAt`，空对话取 Thread 的 `updatedAt`；不为排序改写 Thread 或 Runtime 状态机。
- 按 `activityAt` 倒序，稳定次序使用 `activityAt` 后接 Thread `id`。
- `latestRun` 使用现有 `AgentRuntimeView` 契约，不新增平行运行 DTO。
- 空对话使用显式 `null`，不伪造运行、标题或默认内容。
- 列表标题不进入服务端语义模型；Web 直接展示最新运行的 `state.userMessage`，仅通过 CSS 做视觉截断。

## 6. 后端设计

### Repository

新增有界只读投影，按已授权作用域查询对话及每个对话的最新 Run/Checkpoint。查询必须在数据库层完成用户、租户、项目和画布过滤，不能先加载再在内存中过滤。

列表最多 20 项，避免无界读取。最新运行选择必须使用稳定顺序，且不为每个 Thread 单独发起查询。

### Service

服务先使用现有 `AuthorizeAgentScope` 校验当前用户与画布，再调用 Repository。Checkpoint 必须复用现有 RuntimeState 解析和一致性校验；任何 Run 与 Checkpoint 状态、版本或步数冲突都显式失败。

### Handler

Handler 只负责登录校验、严格查询参数解析、调用 Service 和写统一响应，不承担聚合或权限判断。

## 7. Web 设计

### API client

在现有 `AgentRuntimeClient` 增加 `listThreads(canvasId, limit)`。响应采用严格解析：未知状态、缺失字段、非法日期结构、Run 与 State 冲突都拒绝使用。

### Runtime controller

画布切换时并行处理两个独立事实来源：

1. 读取本地恢复句柄并按现有单 Run 接口恢复。
2. 读取服务端对话历史列表。

选择顺序：

1. 本地句柄指向服务端仍存在的对话时，保留本地选择。
2. 没有本地句柄时，选择服务端列表第一项。
3. 本地句柄读取失败或历史列表失败时，分别显示对应错误，互不伪装成功。

用户选择历史对话后：

- 停止当前事件订阅。
- 清空当前事件游标和选区提交去重状态。
- 采用该对话的 `latestRun`；运行未终结时重新订阅事件。
- 更新当前画布的本地恢复句柄。

用户切换离开正在运行的对话不会取消服务端运行；重新选择后从持久化游标继续恢复。

### Panel

面板头部增加历史入口，打开紧凑列表。每项展示最新用户指令、运行状态和更新时间；空对话显示“尚未开始”。不增加新的整页或复杂管理界面。

## 8. 失败与一致性

- 未登录返回 401；没有画布访问权限返回 403；不存在的画布返回现有授权链定义的错误。
- 历史列表失败时保留明确错误，不展示空列表伪装成功。
- 本地句柄不是权威事实，不能凭本地 ID 绕过服务端授权。
- 服务端响应中的非法 RuntimeState 原地失败，不使用默认状态或旧缓存覆盖。
- 新建 Thread 成功但列表刷新失败时，当前 Thread 仍可使用，同时明确提示历史刷新失败。
- 本阶段接口为只读，不改变 Agent Runtime 状态机、计费和资产事务。

## 9. 测试公共边界

只在以下公共 seam 测试，不测试私有函数或查询实现细节：

1. **HTTP seam**：登录用户按画布获取隔离、稳定排序且有界的对话列表；跨用户、跨租户、跨项目和跨画布事实不可见；非法 limit 明确失败。
2. **Web API seam**：合法聚合响应可解析；未知状态、缺字段、Run/Checkpoint 冲突和非法 `latestRun` 被拒绝。
3. **Agent 面板 seam**：服务端历史加载、跨设备自动恢复、选择对话并恢复订阅、新建后刷新，以及历史请求失败的真实提示。

TDD 按垂直切片执行：先完成 HTTP 列表闭环，再完成 Web 解析闭环，最后完成面板恢复闭环。

## 10. 变更预算与门禁

- 生产职责：服务端历史投影、Web 恢复控制、面板历史入口，共 3 项。
- 生产文件：预计 7–8 个。
- 净新增生产代码：预计 450–650 行。
- 不新增超过 500 行的生产文件；若现有文件职责继续膨胀，新增聚焦模块而不是堆入旧组件。
- 日常只运行 focused tests；稳定后执行全量 Web/Go 测试与 Web production build。
- 不运行真实筷子上游，不使用生产 Key，不修改或清理数据库。

若实际生产改动超过预算 50%，或出现跨状态机、计费、资产事务的新需求，应停止实现并重新拆分设计。
