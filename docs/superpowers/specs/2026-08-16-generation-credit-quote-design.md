# 图片与视频生成积分报价设计

## 目标

图片节点和视频节点在用户调整计费相关参数后，继续在当前生成入口位置显示“闪电标志 + 预计积分”。预计积分必须来自后端唯一计价路径，并与真正提交任务时冻结的积分完全一致。

本设计只解决图片和视频生成的提交前报价。Agent 按 Token 用量结算，调用前无法得到准确账单，不进入本期报价范围。

## 不变量

- 后端是报价与冻结积分的唯一事实源，前端不得独立复制计价公式。
- 报价是只读操作，不创建订单、不冻结积分、不写计费流水。
- 同一用户、模型、参数和生效价格版本下，报价金额必须等于随后提交任务冻结的金额。
- 远程付费模型报价失败时显式失败，不允许在未知价格下提交生成。
- 参数变化后的旧响应不得覆盖新参数的报价。
- 供应商成本、利润率和内部价格快照不得暴露给普通用户。

## 计价维度

### 图片

- 模型决定可用价格策略。
- 分辨率阶梯使用后台发布的 `1K`、`2K`、`4K` 价格。
- 按次计费图片的总价为单张价格乘生成数量。
- 画面比例、种子、提示词、负向提示词和参考图片数量没有独立价格规则时，不改变报价。

### 视频

- 模型决定可用价格策略。
- 分辨率和输入类型共同匹配价格阶梯；输入类型只区分普通生成与参考视频。
- `per_second` 模型按单秒价格乘视频时长；`fixed_request` 模型不因时长变化。
- 每个视频任务独立报价和冻结积分：`per_second` 的 `quantity` 是秒数，`fixed_request` 的 `quantity` 固定为 `1`。若前端一次操作创建多个视频任务，每个任务分别报价和冻结，前端不得把节点数量乘进单个任务报价。
- 没有后台价格规则的比例、提示词、音频开关等参数不改变报价。
- 若启用具有独立价格规则的后处理能力，报价必须包含其附加金额；未配置规则时显式失败。

## 后端设计

新增经过登录和模型访问策略校验的 `POST /api/billing/quotes` 只读接口。请求体固定为：

```json
{
  "type": "任务类型",
  "operation": "任务场景",
  "input": {}
}
```

`input` 复用任务提交的结构化输入契约，但报价服务只投影渠道、模型、能力、数量、分辨率、输入类型、时长及已启用的独立计价后处理参数；不读取提示词正文，也不持久化请求体。接口请求体上限为 64 KiB。

成功响应固定包含：

- `amountMicrocredits`：本次预计冻结的总积分；
- `priceVersion`：生效价格版本；
- `billingMode`：按次或按秒；
- `pricingResolution`、`pricingInputVariant`：实际命中的规格；
- `quantity`：后端最终采用的计费数量；
- `enhancementAmountMicrocredits`：独立计价后处理附加积分，没有附加项时为 `0`。

前端只用现有 `formatCredits` 将 `amountMicrocredits` 从微积分换算为用户可见积分，不参与价格匹配、数量计算或金额舍入。

报价接口与创建计费订单共同调用一个无副作用的报价领域函数。该函数负责模型访问、价格配置、规格归一化、倍率和附加价格计算；订单创建只负责把报价快照写入订单并冻结积分。禁止保留一套报价公式和一套冻结公式。

报价采用无服务端会话的价格版本校验，不新增报价表，也不设置时间型有效期。任务提交请求新增 `quotePriceVersion`，不携带最终金额；后端使用提交参数重新调用同一个报价领域函数。若 `quotePriceVersion` 与当前 `priceVersion` 不一致，返回 HTTP 409、错误码 `PRICE_CHANGED`，并在 `data.currentQuote` 返回当前完整报价。前端展示新报价并要求用户再次提交，禁止静默按新价格扣费。版本一致时，后端以重算结果创建订单、写入报价快照并冻结积分。

## 前端设计

保持现有节点布局和积分位置，不新增卡片、弹窗或计算明细：

- 成功：显示“闪电标志 + 积分数”；
- 请求中：显示“闪电标志 + 计算中”；
- 失败：显示“闪电标志 + 报价失败”，并通过可访问提示暴露真实错误；
- 无需计费的本地模型：不请求远程报价，保持现有非付费状态。

图片或视频的计价参数变化后进行短防抖报价。每次请求携带递增序列或可取消信号，只允许最后一次请求更新界面。模型目录、模型能力和节点参数仍来自现有动态配置，不新增硬编码模型或规格枚举。

远程付费模型只有在当前参数对应的报价成功且参数未变化时才能提交。提交时只携带 `quotePriceVersion`，不携带可由用户篡改的最终金额。

现有算力符号统一替换为产品使用的闪电标志，继续保留当前字号、位置和信息密度。

## 错误与一致性

- 模型未发布价格、规格未匹配、访问策略不允许或报价版本变化均返回结构化错误。
- 网络失败不会复用旧参数的报价；界面进入“报价失败”。
- 后端不得信任前端金额，也不得在报价失败时使用默认价格。
- 报价接口不检查用户余额；余额不足由真正冻结积分的事务返回，避免报价产生写入或锁定副作用。
- 创建订单保存最终价格版本、命中规格、数量、倍率和附加计费快照，支持审计与复算。

## 验收边界

### 后端公开边界

报价 API 覆盖：

- 图片 1K/2K/4K 与多张数量；
- 视频普通/参考视频、分辨率及按秒时长；
- 固定按次视频不被前端数量错误放大；
- 附加计价能力；
- 未配置规格、无权限、报价版本变化和报价只读性；
- 同一请求的报价金额与实际订单冻结金额一致。

### 前端公开边界

画布节点覆盖：

- 当前视觉位置显示闪电标志和后端报价；
- 计价参数变化触发新报价；
- 慢响应不能覆盖更新后的参数；
- 请求中、失败、版本变化和重新提交状态；
- 报价失败时远程付费生成不可提交；
- 不展示供应商成本和利润信息。

## 范围控制

本期不调整后台已有价格，不迁移历史订单，不为 Agent Token 计费制造调用前精确报价，也不改动画布节点整体 UI。生产改动以一个报价领域函数、一个只读 API 和一个前端报价状态模块为边界。
