# 后台用户管理页面排版设计

## 目标

把“用户管理”接入已经落地的后台数据页排版体系，在不改变接口、权限、URL 查询状态和用户操作行为的前提下，统一筛选、批量操作与数据表格的阅读顺序。

## 页面结构

页面保留 `AdminPageFrame` 作为唯一页框架，内容按以下顺序排列：

1. **筛选条件**：搜索、角色、状态、已选筛选标签与重置动作继续使用现有真实状态。
2. **批量操作**：仅在已选择用户时显示，继续使用现有 `AdminBatchBar`，不制造常驻空白区。
3. **用户列表**：标题栏显示当前筛选结果总数和“列设置”；表格、分页、加载、错误与空状态直接置于同一内容区。

不新增用户指标带。当前接口只返回筛选后的 `total`，不足以表达活跃用户、启用状态占比等完整运营事实，把它包装成概览指标会造成语义误导。

## 组件接入

- 使用 `AdminDataLayout` 统一纵向节奏。
- 使用 `AdminFilterSection label="用户筛选"` 包裹现有 `ListToolbar`。
- 使用 `AdminContentSection title="用户列表"` 承载结果总数、列设置、批量操作、表格和分页。
- 不新增页面专用布局组件，不复制请求或选择状态。

## 保持不变的业务契约

- 搜索防抖、角色和状态筛选继续映射 URL 查询参数。
- 页码、每页数量和筛选重置行为不变。
- 列显示偏好继续使用现有本地存储键。
- 用户详情、用户编辑、单用户启停和批量停用行为不变。
- 首次加载、刷新失败、筛选空结果与正常内容继续基于真实服务端事实互斥展示。
- 当前管理员和已停用用户仍不可进入批量停用选择。

## 响应式与可访问性

- 桌面筛选控件紧凑横排，结果操作位于用户列表标题栏。
- 平板筛选控件允许换行，不压缩操作热区。
- 手机筛选单列，按钮热区不低于 44px，表格横向滚动只发生在表格内容区。
- 筛选区使用具名 `region`；用户列表使用连续 `h2` 标题层级；页面继续只有一个 `h1`。

## 状态与错误处理

- 首次加载没有旧数据时显示表格骨架。
- 首次读取失败显示原地重试。
- 刷新失败保留上一次成功数据并显示明确错误。
- 有筛选但无结果时保留现有筛选空状态；无筛选无用户时显示普通空状态。
- 不新增静默回退、默认数据或前端伪成功状态。

## 文件与复杂度预算

生产职责不超过三项：

1. 用户页接入共享数据布局。
2. 用户列表标题操作位整理。
3. 用户页响应式样式清理。

预计修改不超过 4 个生产文件，净新增生产代码不超过 250 行；超过 50% 必须停止并重新评估。不改后端、数据库、DTO、权限或计费。

## 验证

- 定向测试覆盖区块顺序、筛选命名、结果总数、列设置、加载/错误/空状态与既有交互。
- 全量 `bun test`、`bun run build` 通过。
- 重建本地 Docker 镜像，确认后端/Web 健康且仍绑定主仓 `.local/data`。
- 使用真实浏览器验证 1440×900、1024×768、390×844，无页面级横向溢出，表格滚动保持局部。
