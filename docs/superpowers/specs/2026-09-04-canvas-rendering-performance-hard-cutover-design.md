# 画布节点渲染与交互性能硬切换设计

## 目标

把当前画布从“每个节点独立承担复杂视觉动效、原生媒体控件和宽泛派生计算”的实现，硬切换为稳定、扁平、可测量的商业级画布渲染架构。首要目标是修复视频节点在缩放和悬浮时画面、控制条、裁剪边界错位的问题，同时降低多节点场景中的拖动、缩放、调整尺寸和媒体加载成本。

用户确认采用“扁平媒体节点 + 自绘视频控制条”方案。本设计继续保留当前自研 DOM/SVG 画布，不迁移 React Flow、Canvas 2D 或 WebGL，也不复制参考产品代码。

## 已确认事实

在本地真实画布、55% 缩放下测得目标视频节点：

- 非悬浮时，节点根、节点外壳和视频可视尺寸均为 `704 × 396`，节点外壳没有额外 transform。
- 悬浮时，节点根仍为 `704 × 396`，但 `CometCard` 外壳和视频可视尺寸变为约 `752 × 431`，外壳出现 `matrix3d(...)`。
- 视频使用浏览器原生 `<video controls>`；截图中原生控制条只覆盖媒体左侧部分，未与变形后的视频画面和节点边界保持一致。
- `canvas-node-shell` 使用 `overflow: visible`，内部另有圆角裁剪层；3D 变形后节点根、选中描边、媒体裁剪面和浏览器原生媒体控件不再共享同一几何边界。
- 当前所有节点都实例化 `CometCard` 的 Motion values、springs 和 hover 测量逻辑；普通规模画布仍保留重阴影、悬浮放大和眩光。
- 节点调整尺寸期间会逐次更新完整 nodes 数组，并触发项目状态同步；持久化层会同步执行项目级 `JSON.stringify`。
- 当前只裁剪不可见节点，连接线仍按完整连接集合渲染；可见节点缓冲区明显大于屏幕。

因此，截图问题不是素材文件损坏，也不是单纯的宽高比差异，而是媒体控件、节点动效和画布缩放共同造成的合成层与几何契约冲突。

## 设计原则

1. **单一几何真源**：节点根尺寸、媒体裁剪面、选中轮廓和命中区域必须使用同一 width/height，不允许视觉层通过 3D transform 改变边界。
2. **单一媒体表面**：媒体节点只允许一层可见圆角裁剪面；标题、状态、工具和连接点作为独立覆盖层或兄弟层，不再创建圆角套圆角。
3. **手势期间零业务提交**：拖动、缩放、调整尺寸期间只更新 DOM/CSS 预览；手势结束时提交一次领域状态。
4. **只渲染有价值的内容**：节点、连接线和媒体按视口距离分级，屏幕外资源不占用持续解码、动画或复杂 DOM 成本。
5. **显式失败**：媒体加载失败、尺寸不合法、持久化失败和同步失败必须保留可定位事实，不用默认素材或静默回退掩盖。
6. **硬切换**：删除旧 3D 节点动效和浏览器原生视频控制条路径，不保留双轨兼容分支。

## 方案选择

### 采用：优化现有 DOM/SVG 画布

- 保留已经存在的 CSS variable 视口预览和 DOM 拖动预览。
- 重建节点表面、视频控制层、可见性派生和提交边界。
- 优点是变更集中、可回滚，现有节点数据、连接语义和生成链路无需迁移。

### 不采用：迁移 React Flow

当前产品已经拥有节点、连接、批次、Frame、生成状态和协作协议。迁移只能更换渲染容器，无法自动解决媒体控制、持久化和大图派生问题，反而会扩大回归面。

### 不采用：Canvas 2D / WebGL 全量渲染

这些方案适合超大规模纯图形场景，但当前节点包含文本编辑、媒体播放、表单和无障碍控件。全量迁移会重新实现大量 DOM 能力，不符合当前投入产出比。

## 目标架构

### 1. CanvasInteractionRuntime

新增职责单一的交互运行时，统一管理 pan、zoom、node drag 和 node resize 的瞬时预览：

- 输入：规范化指针/滚轮事件、当前 viewport、目标节点初始几何。
- 输出：通过 CSS custom properties 写入 viewport 或单节点 preview transform/size。
- 完成事件：手势结束时发出一个结构化 commit，页面状态只消费 commit，不消费每帧预览。
- 取消事件：恢复到初始几何，不写入项目状态。

运行时不得读取完整 nodes/edges，不得持久化、发网络请求、执行序列化或写业务日志。

### 2. CanvasNodeSurface

`CanvasNode` 继续作为节点行为边界，但把视觉表面拆成明确层级：

1. `node-element`：唯一的位置与尺寸容器，允许连接点和外部工具溢出。
2. `canvas-node-surface`：唯一圆角媒体/内容裁剪面，`overflow: clip`，无 3D transform。
3. `canvas-node-outline`：绝对定位、无布局影响的选中/关联/失败轮廓。
4. `canvas-node-overlays`：标题、状态、资源标签与悬浮操作。
5. `canvas-node-handles`：连接点和尺寸手柄，位于裁剪面外部。

删除节点对 `CometCard` 的依赖。默认和悬浮状态不得改变节点几何尺寸，不使用 glare、perspective、rotateX、rotateY、translateZ 或 hover scale。

### 3. CanvasVideoPlayer

视频节点改用产品自绘控制层，不再设置原生 `controls`：

- `<video>` 只负责播放、解码、帧展示和原生全屏能力。
- 控制层提供播放/暂停、进度、当前时间/总时长、静音和全屏。
- 控制层使用普通 DOM，宽度严格为节点表面的 `100%`，与画布缩放使用同一变换链。
- 控制事件必须阻止画布 pan/zoom/drag，不得误选节点或移动画布。
- 键盘支持 Space/Enter 播放暂停、方向键调整进度、M 静音；按钮具有明确 `aria-label`。
- 元数据尚未加载时显示确定的禁用状态；播放或元数据错误复用现有显式失败界面。
- 节点离开近视口后暂停播放并卸载非必要监听；再次进入时不自动播放。

图片继续使用浏览器图片元素，但必须与视频共享 `canvas-node-surface`、object-fit 和加载状态契约。音频播放器本阶段保留原生控件，因为其不位于缩放媒体画面内；后续若实测出现相同问题，再单独设计统一音频控制层。

### 4. CanvasRenderIndex

建立只在结构或几何 commit 后更新的空间索引：

- 节点几何 commit 时更新对应条目，不在 viewport 每帧重建索引。
- 视口变化只查询当前视口、近视口缓冲区中的节点和连接。
- 连接可见性的事实依据是端点或连接路径包围盒与缓冲视口相交。
- 批次和 Frame 隐藏状态预先构建 id map，禁止在节点/连接过滤过程中重复 `find`。

渲染分三级：

- **Visible**：完整节点内容、可交互媒体和连接线。
- **Near viewport**：节点轻量占位/已解码静态预览，不播放视频、不运行动画。
- **Offscreen**：不挂载节点内容和连接 SVG，只保留索引数据。

### 5. CanvasDocumentCommitBoundary

统一领域状态与持久化边界：

- drag/resize/pan/zoom preview 不修改项目文档。
- 节点拖动和调整尺寸结束时，每个手势最多产生一次节点几何 commit。
- viewport 结束/空闲后最多产生一次 viewport commit。
- 结构变更、媒体结果、提示词和节点状态继续按现有事实提交，但不得与每帧交互预览混合。
- IndexedDB 序列化必须发生在已调度的持久化任务中，而不是 store setter 的同步热路径。
- 协作 diff 只在 commit 后计算，位置预览不广播完整文档。

保存状态必须明确区分 `idle / saving / saved / failed`；失败保留未保存事实并允许显式重试，不制造“已保存”假象。

## 视觉契约

本设计覆盖 `2026-08-13-canvas-media-node-polish-design.md` 和 `2026-08-13-canvas-node-ui-standard-design.md` 中与节点外壳、媒体控制和性能相关的条款；未涉及的业务状态和节点家族契约继续有效。

### Tokens

- 节点表面圆角：`12px`。
- 节点内部控件圆角：`8px`。
- 默认边界：1px 中性弱边界；媒体铺满时由唯一 outline 表达，不再额外套边框。
- 选中轮廓：2px 主题焦点色，使用 outline/box-shadow，不改变布局尺寸。
- 默认阴影：无。
- 悬浮阴影：只允许现有 `--shadow-sm`，且不得改变几何。
- 危险/失败：沿用主题 danger token，不能只用颜色，必须同时提供图标或文字。
- 节点标题：`13px / 20px / 500`。
- 状态与元数据：不得低于 `11px / 16px`。
- 视频控制层高度：32px；图标 16px；桌面点击热区至少 32px，触摸环境至少 44px。
- 间距只使用 `4 / 8 / 12 / 16px`。
- 悬浮/显隐过渡：`120–160ms`；拖动、缩放和 `prefers-reduced-motion` 下关闭。

## 数据流

### 视口交互

`pointer/wheel -> normalize -> CanvasInteractionRuntime -> CSS viewport preview -> gesture end/idle -> viewport commit -> optional persistence`

### 节点拖动与尺寸调整

`pointer down -> capture initial geometry -> CSS preview -> pointer up -> one geometry commit -> render index update -> collaboration diff -> scheduled persistence`

### 视频播放

`custom control -> video element API -> media events -> local player state -> control projection`

播放器状态不写入项目文档；资源 URL、时长等事实元数据继续使用当前节点数据契约。

## 错误处理与可观测性

- 媒体元数据加载、播放、全屏和资源请求失败必须携带 nodeId、资源 URL 摘要和浏览器错误类型进入现有诊断日志。
- 交互 commit 拒绝非法尺寸或非有限坐标时显式报错并恢复初始预览；不得写入 `NaN` 或负尺寸。
- 持久化与协作失败不得阻塞本地交互，但必须维持 failed 状态和待同步事实。
- 性能探针只在测试/诊断入口启用，生产默认不输出每帧日志。

## 验收与性能门禁

### 自动化契约测试

- 媒体节点默认、悬浮、选中和拖动时 `node-element`、surface 与媒体的几何尺寸一致。
- 节点悬浮后 computed transform 不得包含 3D rotate/translate/scale。
- 视频节点不使用原生 `controls`，自绘控制条宽度与 surface 一致。
- 自绘控制条的播放、暂停、seek、mute、fullscreen、键盘和事件隔离行为通过测试。
- resize/drag 每个手势只提交一次状态，取消不提交。
- viewport 查询只返回 visible/near 节点与相交连接；边界节点不闪烁。
- IndexedDB 序列化不发生在 pointermove/mousemove/wheel 同步调用栈。

### 确定性浏览器基准

增加可重复 fixture，并在 Chromium、Firefox、WebKit 至少验证以下规模：

- 50 节点 / 50 媒体 / 300 连接。
- 200 节点 / 100 媒体 / 1,000 连接。
- 500 节点 / 200 媒体 / 3,000 连接。

每组运行 pan、zoom、单节点拖动、20 节点批量拖动、resize 和视频控制操作。目标：

- 常规桌面环境交互目标 60 FPS，P95 帧耗时低于 20ms。
- 手势期间不出现超过 50ms 的主线程 Long Task。
- pointermove/wheel 热路径不出现项目级 JSON 序列化、网络请求或全量 nodes/edges 扫描。
- 屏幕外视频不播放，远离视口的媒体内容不挂载。
- 相同画布连续运行 2 分钟后帧耗时和内存不出现周期性恶化。

环境性能差异较大时，CI 以“无热路径禁用行为 + 相对基线不回退超过 15%”作为稳定门禁；固定开发机保留绝对帧耗时报告。

### 真实浏览器验收

- 在当前真实画布复验用户截图中的视频节点，分别检查 25%、55%、100%、200% 缩放。
- 检查普通、悬浮、选中、拖动、播放、全屏和调整尺寸状态，画面、控制条、边界必须始终重合。
- 检查图片、视频、音频、文本、脚本、配置、Frame、批次和连接点没有行为回归。
- 检查明暗主题、触控板、鼠标滚轮、Windows Chrome/Edge，以及 Firefox/WebKit 自动化结果。
- Web 类型检查、定向测试、全量测试、生产构建、bundle budget 和 `git diff --check` 全部通过。

## 变更预算

- 生产职责：5 个（交互运行时、节点表面、视频播放器、渲染索引、提交边界）。
- 生产文件：预计 12–18 个。
- 净新增生产代码：预计 500–900 行。
- 删除旧 3D/眩光/重复交互代码：预计 200–400 行。
- 测试与 fixture：预计新增 8–12 个文件。
- 不新增运行时或生产依赖；允许增加仅用于 Chromium、Firefox、WebKit 门禁的固定版本测试依赖，该依赖不得进入生产包。不得修改数据库、计费、模型、生成、资产所有权或 Agent 协议。

若实际需要新增第六个生产职责、超过 24 个生产文件，或发现必须改变节点/协作持久化 DTO，停止实现并重新确认架构范围。

## 阶段与回滚

1. 建立当前缺陷的 DOM 几何回归测试和确定性画布 fixture。
2. 硬切换扁平节点表面，删除 `CanvasNode` 对 `CometCard` 的依赖。
3. 接入自绘视频控制层并完成媒体节点浏览器回归。
4. 统一拖动/缩放/resize 的 preview/commit 边界，移出同步序列化。
5. 接入节点与连接空间索引、媒体分级挂载。
6. 执行规模化基准、完整真实浏览器验收和独立代码审查。

每个阶段形成职责单一、可独立回滚的 Conventional Commit。回滚以提交为单位，不保留运行时 feature flag 或旧渲染双轨。任何阶段未满足门禁时停止在本地分支，不合并、不部署。

## 明确暂缓

- 不迁移画布技术栈。
- 不重做节点业务类型、连接规则、生成状态机或 Agent 操作协议。
- 不修改音频原生播放器，除非真实浏览器复验证明同类缩放缺陷存在。
- 不增加新的视觉特效、缩略图服务或媒体转码链路。
- 不处理与本次画布渲染、交互性能无关的历史页面重构。

## 完成定义

只有当用户截图中的错位能够由自动化测试稳定复现并转绿、三档规模基准满足门禁、真实画布多缩放验收通过、代码审查无未解决 Critical/Important、且所有改动可按独立提交回滚时，本次画布优化才算完成。
