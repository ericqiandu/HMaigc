# 筷子统一凭据与全站 Agent 默认模型配置设计

## 目标

筷子科技账号只维护一份 Base URL 与 API Key，全部模型系列共用该账号凭据；管理员同时在后台指定全站唯一的 Agent 文本模型。普通用户的画布不显示模型选择入口，只使用后台已确认的配置。

## 统一凭据硬切

- Provider adapter 的 family 只描述模型能力与发布目录，不再拥有独立 Key。
- 现有账号下所有活动系列凭据在启动迁移中逐条解密并比较原文；全部一致时才创建唯一账号级凭据根。
- 迁移在一个数据库事务内重绑全部筷子模型、禁用旧系列凭据并保存账号级凭据；任何不一致、解密或写入错误都整体回滚并阻止服务启动。
- 旧系列凭据及版本不删除，仅供已冻结的历史任务按原 ID 继续解析；新任务与模型发布只能绑定账号级凭据。
- 后台删除系列级 Key 的保存和验证入口，只保留一份公共 Base URL、API Key、健康状态、余额与验证操作。
- 不保留系列级新写入接口、自动选 Key 或运行时模型降级。

## 领域边界

- 模型目录继续负责渠道、模型能力、启停与定价事实，全部筷子模型绑定同一个账号级凭据 ID。
- 独立系统设置 `agent_default_model` 只保存被选中的模型记录 ID，不复制渠道、密钥、模型名或价格。
- 管理员设置接口只能选择已启用、已完成定价且能力为 `text` 的系统模型；保存与读取均重新验证这些事实。
- 每次 Agent 调用继续由服务端按模型目录解析真实渠道与凭据，前端不接触密钥。

## 后台交互

- 在 `/admin/model-pricing` 增加独立的“Agent 模型配置”区块；筷子账号页只展示一份公共凭据配置。
- 下拉候选项来自当前模型目录，只展示符合 Agent 使用条件的文本模型。
- 保存成功立即刷新后台设置和登录用户的系统模型事实，并记录管理员审计事件。
- 被选模型后续停用、删除或失去有效定价时，配置视为失效，不自动切换其他模型。

## 用户端交互

- 移除 Agent 输入区的模型选择按钮、模型菜单及 Agent 模型选择摘要。
- Agent 请求始终使用后台返回的全站默认模型。
- 未配置或配置失效时，发送操作不可用，并明确提示“管理员尚未配置可用的 Agent 模型”。
- 不保留旧的用户选择、不读取第一个文本模型、不做模型降级。

## 契约与失败处理

- 管理端提供读取与更新 Agent 默认模型的鉴权接口。
- 登录态系统模型响应包含经过服务端验证的默认 Agent 模型引用；无效时返回空值。
- 更新失败不改变原设置；审计写入与设置保存属于同一交付结果，任何失败都显式返回。

## 验证

- 服务端：统一凭据的一致/不一致迁移、事务回滚、历史任务冻结读取、管理员权限、候选资格、设置保存/读取、模型停用后的失效、审计事件。
- 前端后台：候选过滤、保存与错误状态。
- 画布：不再渲染模型选择入口；有效配置用于请求；缺失配置禁止发送且无隐式兜底。
- 最终执行受影响测试、Web 构建、Go 全量测试与 diff 检查。

## 变更预算

- 生产职责：统一账号凭据、事务迁移与完整性门禁、Agent 默认模型设置、后台/画布消费，共 4 项。
- 预计生产文件不超过 16 个，净新增生产代码约 900 行以内，分两个可独立回滚提交。
- 不改模型计费算法、Agent 工具协议或数据库表结构。
