# HMaigc 首页布局重构设计

## 目标

在不删减 HMaigc 功能、不改变数据接口和业务行为的前提下，参考 Updream 首页的信息密度、空间节奏和对齐关系，重构首页排版。目标是让 Agent 输入成为首屏中心，同时让最近项目进入首屏下沿，并以紧凑、克制的三列卡片呈现官方技能。

参考页面：<https://www.updream.cn/>

本设计只借鉴布局与交互语言，不复制对方 Logo、文案、图片、品牌标识或受保护资产。

## 已确认约束

- 保留左侧完整菜单：主页、创作、画布、任务、素材、技能均不删除。
- 保留 HMaigc Logo、账户区、积分、会员、公告和现有主题切换。
- 保留首页 Agent Composer 的模型、技能、执行模式、附件和发送能力。
- 保留项目和技能的真实接口、加载状态、错误状态及跳转路径。
- 深色模式贴近参考站的空间与明度层级；浅色模式使用同一几何布局和 HMaigc 浅色主题。
- 不修改画布、项目详情、技能详情和后台页面。

## 当前问题与事实

在 1092 × 912 的真实桌面视口中：

- HMaigc Hero 占据约 912px 高度，最近项目从约 y=795 才开始，首屏几乎看不到有效项目内容。
- 参考站的输入区集中在约 620px 高的首屏核心段，最近项目从约 y=670 开始进入视野。
- HMaigc 技能卡在当前宽度下为两列、单卡约 430 × 180，使用高饱和渐变；参考站为三列、单卡约 281 × 180，强调封面、标题、描述和使用信息。
- HMaigc 的 Hero、项目区和技能区采用不同的左右起点；参考站由统一内容列控制标题、卡片和操作入口。
- 当前首页功能完整，问题集中在 CSS 几何、卡片组件表达和首屏节奏，不需要重构数据层。

## 方案选择

采用“结构复刻、品牌保留”。

不采用以下方案：

- 全量视觉克隆：会把 HMaigc 变成参考站的品牌副本，也会破坏现有 Design.md 定义的浅色主题。
- 只调局部间距：无法解决 Hero 过高、区域起点不统一和技能卡密度不足这三个结构问题。

## 页面结构

### 1. 顶部与侧边导航

- 顶部保持现有 HMaigc Header 和账户操作，桌面高度收敛为 64px；移动端为 56px。
- 左侧导航保留全部六个入口，桌面维持 48px 宽的浮动轨道。
- 不增加新的导航层，不复制参考站的菜单数量。
- Header 与页面背景通过透明度和轻度模糊形成一层导航深度，不额外增加描边容器。

### 2. Hero 与 Agent Composer

- 桌面 Hero 目标高度 600–640px；从 Header 下方开始计算，不再使用接近完整视口的 912px 高度。
- 标题位于 Hero 视觉中心上方，桌面 32px、移动端 26px，行高紧凑。
- Composer 桌面宽度 700px，保持现有内部组件和功能；只调整外部位置、背景、边框明度和垂直节奏。
- 快捷技能入口紧贴 Composer 下方，横向滚动而非换成多行大按钮。
- Hero 背景仅承担氛围，不影响文字和 Composer 对比度；减少亮色雾化对内容区的干扰。

### 3. 最近项目

- 与 Hero 使用同一内容列，桌面最大宽度 884–900px。
- 标题栏高度 28px，项目网格紧随其后。
- 桌面展示新建项目加最多四个最近项目；卡片约 162 × 224，保持 16px 单层圆角。
- 中等宽度降为 3 列，移动端采用横向滚动卡带，避免卡片被压成过窄的两列。
- 项目数据、排序、错误提示和加载骨架保持现有逻辑。

### 4. 官方技能

- 与项目区使用相同左右起点和最大宽度。
- 桌面三列、两行，单卡高度约 180px；中等宽度两列，移动端单列。
- 卡片改为低饱和深色/浅色表面，保留真实技能封面。移除高饱和彩色渐变。
- 卡片内容结构为：封面、标题、官方来源、两行描述、版本/来源事实。
- 卡片只保留一层可见圆角边界，不在内部继续套圆角卡片。
- 加载失败必须显式展示原因和重试，不使用静态技能兜底。

### 5. Footer

- 保留现有法律链接和版权信息。
- 与技能区保持 64–80px 间距，不在首页中间插入额外营销区。

## 主题与视觉令牌

### 深色模式

- 页面背景以近黑为主，不使用纯黑大面积叠加多层面板。
- Composer 和卡片使用一档表面明度差表达层级。
- 文字分为主文字、次文字和弱文字三档，不依赖边框制造层级。
- HMaigc 品牌渐变只用于标题或极小状态信号，不扩散到技能卡背景。

### 浅色模式

- 使用相同布局、尺寸和组件层级。
- 页面背景使用 Design.md 的浅灰体系，卡片表面略亮于页面背景。
- 不把深色卡片简单反相，保持封面和文字的实际对比度。

## 响应式规则

- `>= 1200px`：统一约 900px 内容列，项目 5 列、技能 3 列。
- `768–1199px`：内容列随视口收缩，项目 3 列、技能 2 列。
- `< 768px`：Header 收敛，侧边导航不覆盖正文；Hero 高度由内容决定；项目横向滚动；技能单列。
- 所有主要交互目标至少 40px；键盘焦点状态保持现有可访问性契约。

## 组件与职责

- `updream-home-page.tsx`：只负责区域装配、滚动状态和延迟加载。
- `updream-hero.tsx`：保留 Agent 草稿与创建项目流程，只调整外部结构 class，不改提交逻辑。
- `updream-recent-projects.tsx`：保留查询与排序，调整卡片 DOM 层级和响应式容器。
- `updream-skills-section.tsx`：保留技能目录请求，重构卡片表现，移除渐变表。
- `updream-home.css`：作为首页布局与主题映射的唯一真源，删除冲突规则，不新增平行补丁文件。
- Header/Footer 只在现有文件内做必要尺寸调整。

## 数据流与错误处理

- Agent 创建项目、参考图片上传、模型与技能选择流程完全不变。
- 最近项目继续使用 React Query 的 `listProjects`；错误原样展示并允许用户重试。
- 技能继续使用 `listSkillsCatalog`；无结果展示真实空状态，失败展示真实错误。
- 禁止使用假项目、假技能、静态回退卡片掩盖接口问题。

## 性能要求

- 不新增 UI 框架或大型依赖。
- 保留最近项目与技能区的路由级延迟加载。
- 技能封面继续 `loading="lazy"`；首屏背景不得引入额外高码率媒体。
- 不在滚动热路径增加 DOM 扫描、网络请求或全量状态派生。
- Web 生产构建和现有 bundle budget 必须通过。

## 测试与验收

- 为首页结构补充 focused 组件测试：菜单完整、项目/技能内容真实、无渐变回退。
- 跑 Web 全量测试、TypeScript 类型检查和生产构建。
- 使用真实本地页面在桌面与移动断点做视觉验收：
  - 首屏可见最近项目标题及至少一行卡片上沿。
  - Composer 所有原有操作仍可见、可聚焦、可选择。
  - 左侧六个菜单入口完整。
  - 深浅主题下没有文字对比度丢失或卡片层层圆角。
  - 技能区桌面三列、中等宽度两列、移动端单列。

## 变更预算

- 生产职责：Hero 空间结构、项目卡片密度、技能卡片表达，共 3 类。
- 预计生产文件：6–8 个。
- 预计净调整：400–650 行；以删除冲突 CSS、重写单一首页样式为主。
- 昂贵门禁：Web 全量测试、生产构建、bundle budget、桌面/移动真实浏览器验收。
- 暂缓项：其他页面统一、导航信息架构调整、新营销模块、账户区重构。
