# 后台页面排版优化设计

## 目标

在不改变后台路由、接口、权限和业务行为的前提下，统一后台页面内部的阅读顺序、内容密度和响应式排版。第一阶段以“数据概览”为完整样板，同时沉淀可被其他后台页面复用的排版组件与样式契约。

本轮只解决页面内容布局，不继续扩展上一阶段已完成的主题、菜单、品牌色、侧栏宽度、内容宽度和固定顶部栏设置。

## 设计原则

- 对齐根目录 `Design.md` 与 `web/DESIGN.md`，采用“概览指标 → 条件筛选 → 数据内容”的纵向顺序。
- 使用现有 Ant Design、后台语义 Token 和共享状态组件，不引入 ProComponents 或第二套后台框架。
- 信息密度优先于装饰；通过留白、对齐、背景明度和弱分隔表达层级。
- 一个区块最多一层可见边界；禁止指标卡套卡、筛选卡套表格卡。
- 业务请求、URL 筛选状态、表格数据与错误处理保持原契约。
- 390px、1024px、1440px 三档均不得出现页面级横向溢出。

## 页面结构

### 共享页面框架

`AdminPageFrame` 继续作为后台页面唯一页面框架，保持：

1. 页面标题、简短说明和页面级操作位于同一页头节奏。
2. 页面级操作只承载刷新、导出、创建等动作；筛选不进入页头。
3. 主内容通过统一的纵向间距组织，不由各页面随意叠加 `margin`。

### 数据页共享组件

新增一组只负责排版的轻量组件，放在后台共享组件目录：

- `AdminDataLayout`：数据页根容器，统一各区块的纵向节奏。
- `AdminMetricBand`：连续指标带，支持分组标题、说明和若干指标；指标之间只使用弱分隔，不为每个数字建立独立卡片。
- `AdminFilterSection`：筛选区语义容器，接收现有真实筛选控件与操作，不拥有查询状态。
- `AdminContentSection`：图表、标签页和表格的内容分区，提供标题、说明和可选操作位。

组件只负责语义结构和 className，不复制数据请求、筛选、分页或表格逻辑。

## 数据概览样板

数据概览按以下顺序重排：

1. **运行概览**：队列、活跃用户、生成任务、请求成功率、P95 耗时，使用一条连续指标带。
2. **商业指标**：上游成本、积分营收、积分毛利、冻结积分，使用第二条连续指标带；与运行指标保持相同尺寸和数字格式。
3. **筛选条件**：时间、用户、模型、渠道、能力与重置动作统一放入筛选区；桌面采用稳定栅格，平板收为两列或四列组合，手机单列。
4. **使用趋势**：图表作为独立内容分区，图例与说明在标题下，不增加装饰性外框。
5. **分析明细**：模型分析、用户活动、异常定位继续使用现有 Tabs 与 Table，但共用内容区标题、表格边界和底部留白。

首次加载、空状态、错误和刷新保留现有真实事实表达，不制造零指标或伪成功。

## 响应式规则

- `>=1280px`：指标按内容数量横向排列；筛选字段使用稳定栅格；页头标题与操作同排。
- `640px–1279px`：指标允许两列或自适应换行；筛选区最多两列；表格只在自身内容区滚动。
- `<640px`：指标纵向排列或两列紧凑呈现；筛选单列；页面操作等宽换行；主要控件热区不低于 44px。
- 图表在窄屏保持可读高度，不通过隐藏或裁切数据解决拥挤。

## 状态与可访问性

- 分区标题使用连续的 `h2` 层级，页面保留唯一 `h1`。
- 指标使用语义 `dl/dt/dd` 或等价结构，数值不只依靠颜色表达状态。
- 筛选区域具备明确的区域名称；所有输入继续保留现有 label。
- 加载、失败、空数据和成功内容互斥展示；失败保留原地重试。
- 不引入自动动画；只保留现有 hover、focus-visible 和受 reduced-motion 控制的短过渡。

## 文件与复杂度预算

生产职责不超过三项：

1. 共享数据页排版组件。
2. 数据概览结构接入。
3. 后台数据页共享样式与响应式规则。

预计不超过 8 个生产文件、净新增生产代码约 500 行；任何超出 50% 的增长必须停止并重新评估。单个新增生产文件不得超过 300 行。

## 验证

- 聚焦测试覆盖共享组件语义、区块顺序和响应式 class 契约。
- 保持现有数据概览筛选、刷新、导出、图表、Tabs、表格及错误状态测试通过。
- 全量 `bun test` 与 `bun run build` 通过。
- 重新构建本地 Docker 镜像，确认 backend/web 健康且绑定既有 `.local/data`。
- 真实浏览器验证 1440×900、1024×768、390×844，检查区块顺序、控件换行、表格局部滚动和无页面级横向溢出。

## 暂缓项

- 不逐页重写会员、积分商城、模型定价等复杂业务表单。
- 不改变后台信息架构、菜单名称、路由或权限。
- 不引入 ProComponents、Headless UI 或其他新布局依赖。
- 不修改后端、数据库、接口 DTO、计费或运营数据。
