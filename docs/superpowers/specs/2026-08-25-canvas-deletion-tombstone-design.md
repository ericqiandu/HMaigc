# 画布跨浏览器删除事实设计

## 业务目标

用户在任一浏览器删除画布后，其他浏览器、其他标签页和离线后重新上线的旧客户端都不得用本地缓存将同一画布重新创建。删除必须保持幂等、权限隔离、事务一致和可审计定位。

## 已确认根因

当前同步协议只返回仍然存在的画布。前端把“远端列表中不存在该 ID”同时解释为“远端已删除”和“本地新画布尚未上传”，并统一选择后者；另一浏览器保存的旧本地画布因此再次调用创建接口。后端硬删除画布后不保留删除事实，创建接口只检查当前画布表，因而接受相同 ID。

## 单一事实模型

新增 `canvas_project_deletions`：

- `canvas_id`：全局唯一、永久阻止同一 ID 再创建；
- `user_id`、`team_id`：保存删除时的个人或团队作用域，用于向有权参与该画布同步的账号返回删除事实；
- `deleted_by_user_id`：记录执行删除的真实用户；
- `deleted_at`：服务端删除时间，也是客户端合并事实的版本时间。

删除事务先写入墓碑，再删除变更记录、协作者、分享和画布正文；任一步失败全部回滚。墓碑不保存标题、节点、提示词或媒体地址。

## API 契约

`GET /api/canvas-projects` 返回：

```json
{
  "projects": [],
  "deletions": [
    { "id": "canvas-id", "deletedAt": "2026-08-25T00:00:00Z" }
  ]
}
```

个人删除事实只对原所有者可见；团队删除事实只对当前有效团队成员可见。重复 `DELETE` 对仍有权看到该删除事实的用户返回成功，对无权用户仍返回 404。

`PUT /api/canvas-projects/:id` 若 ID 已有墓碑，返回 HTTP 410，文案为“画布已删除，不能使用原 ID 重新创建”。该失败是跨浏览器删除事实，不得重试为创建，也不得自动生成替代 ID。

## 前端同步契约

同步顺序固定为：

1. 读取远端画布摘要与删除事实；
2. 先从本地集合移除所有墓碑 ID；
3. 再合并仍存在的远端画布和真正未上传的本地新画布；
4. 若列表读取与创建之间发生并发删除，创建收到 410 后立即移除同 ID 本地缓存并持久化；
5. 其他错误继续显式失败并保留本地数据等待人工或下一次明确重试。

## 一致性与边界

- 删除写入和画布正文删除必须处于同一数据库事务。
- 同一 ID 的创建与删除由数据库现存记录和墓碑唯一键共同裁决。
- 删除失败不得先从本地消失；现有待删除恢复机制继续负责当前浏览器的网络失败。
- 墓碑是小型不可变同步事实，不参与存储配额，不包含用户内容。
- 历史上已经硬删除且当前仍被旧浏览器复活的画布，需要在本版本上线后再删除一次，才能形成首条墓碑；不伪造历史删除记录。

## 验收场景

- 浏览器 A 删除、浏览器 B 同步后本地画布消失且数据库不再出现该 ID；
- 浏览器 B 在列表读取后、创建前遇到并发删除，410 会清除旧本地画布；
- 同一用户重复删除幂等成功；
- 其他用户不能查询墓碑或把重复删除当作成功；
- 团队管理员删除后，团队成员同步获得删除事实；
- 删除事务失败时画布、分享和墓碑都保持原状；
- 非 410 的创建错误不得被吞掉或误删本地画布。
