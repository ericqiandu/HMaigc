# 模型中心「渠道与模型」页面统一排版设计

## 业务目标

把 `/admin/models` 纳入当前后台统一的数据页语言，使管理员按“接入概览 → 渠道筛选 → 渠道目录”的固定顺序完成模型渠道维护。改造只调整页面信息层级、共享表面和响应式表现，不改变渠道密钥、模型目录、发布状态、并发限制或调用协议。

## 当前事实

- 模型中心包含“渠道与模型、筷子账号、价格与 Agent”三个独立路由，本轮只改造“渠道与模型”。
- 页面现有真实能力包括渠道新增与编辑、密钥留空保留、接口类型选择、并发限制、启停、渠道内模型管理、搜索筛选、分页和刷新。
- 渠道目录与渠道内模型目录分别具有加载、保留旧数据刷新、失败和空数据状态；这些事实不得合并或伪装。
- 编辑抽屉已有脏状态与保存期间关闭保护，模型管理由独立组件负责。

## 采用方案

使用后台现有共享数据布局，不新增第二套卡片或模型中心专用框架：

1. **渠道接入概览**：复用 `AdminMetricBand`，展示渠道总数、已启用渠道数、已登记模型数和当前接入提示。指标仅来自已成功读取的服务端结果；首次加载失败时不显示零值。
2. **渠道筛选**：复用 `AdminFilterSection` 与现有 `ListToolbar`，保留关键词、接口类型、启用状态、重置和结果数量；新增渠道继续作为页面级主操作。
3. **渠道目录**：复用 `AdminContentSection` 与 `TableSurface`，集中承载渠道表、分页、首次加载骨架、刷新失败、空状态和行级操作。
4. **编辑与模型目录**：继续使用现有渠道编辑 Drawer 和 `ChannelModelManager`，只对齐共享弹层主题、间距和移动端尺寸，不改业务提交路径。

页面顺序固定为“模型中心流程导航 → 页面标题与主操作 → 接入概览 → 筛选条件 → 渠道目录”。

## 视觉与响应式规则

- 只使用后台语义 Token、共享数据页组件和既有 Ant Design 控件。
- 每个独立区块最多一层可见圆角边界；筛选、表格与分页不得继续形成嵌套卡片。
- 桌面端指标横向排列，筛选保持紧凑栅格；1280px 以下切换为现有后台移动壳层。
- 390px 下筛选单列、页面操作保持 44px 热区；宽表只在内容区内部滚动，页面级横向滚动为零。
- 日间和夜间保持相同结构、字号和密度，只切换语义颜色。

## 状态与安全边界

- 首次读取失败使用 `AdminContentError` 替代依赖渠道数据的指标与表格，保留真实原因和重试入口。
- 保留旧数据的刷新失败继续展示旧目录，并在内容区明确标注失败；不得清空为零渠道。
- 密钥仍为 write-only；前端、日志、测试夹具和错误文案不得回显真实 Key。
- 无真实改动时保存按钮保持禁用；保存期间禁止关闭和重复提交。
- 不修改 API、DTO、后端、数据库、权限、计费、模型发布规则或上游调用链。

## 实施边界与预算

- 生产职责：顶层信息架构、共享表面接入、响应式样式，共 3 项。
- 生产文件不超过 6 个，净新增生产代码不超过约 400 行。
- 不同时改造筷子账号、价格与 Agent、音色管理或其他后台页面。
- 若实现需要修改后端契约或超出预算 50%，停止实施并重新确认范围。

## 验收

- 真实页面按既定顺序展示流程导航、概览、筛选和渠道目录。
- 新增、编辑、密钥保留、启停、渠道内模型管理、刷新、筛选和分页流程保持可用。
- 首次加载、刷新失败、空目录和成功目录互斥且事实准确。
- 1440×900、1024×768、390×844 的日间与夜间主题无页面级横向溢出。
- 聚焦测试、全量 Web 测试、生产构建和包体预算通过。
- 只重建无状态 Web 容器；本地后端和 `.local/data` 不变。
