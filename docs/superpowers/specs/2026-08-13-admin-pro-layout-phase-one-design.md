# HMaigc 管理后台 Pro 化第一阶段设计

## 1. 业务目标

将现有管理后台从深色、层级接近的自定义界面，硬切为以 Ant Design Pro 为排版参照的企业运营后台，同时保留 HMaigc 的业务信息架构与品牌身份。

第一阶段只建立可复用的后台标准，并用“数据概览”完成真实业务样板。它不是全后台换肤，也不修改任何业务接口、权限、数据库、计费或发布升级流程。

## 2. 决策与边界

### 2.1 已确认决策

- 采用渐进式统一方案。
- 后台首次进入默认浅色。
- 后台提供显式浅色 / 深色切换，并记住管理员选择。
- 页面排版采用 Ant Design Pro 的企业后台逻辑，而不只是替换颜色。
- 继续使用现有 React、Vite、React Router 与 Ant Design。
- 不引入 Umi、ProLayout、MUI、Mantis 或第二套组件系统。
- 现有 `AdminShell`、后台路由、权限和业务页面作为改造基础。

### 2.2 第一阶段范围

1. 后台独立主题作用域与主题切换入口。
2. 桌面侧栏、顶部栏、面包屑、返回创作台和账号/主题操作区。
3. 统一的 `AdminPageFrame` 页面标题、说明和操作布局。
4. “数据概览”页面改造为标准样板。
5. 公共后台设计 Token 与响应式规则。
6. 桌面、平板与移动端的基础回归。

### 2.3 明确暂缓

- 模型、渠道、定价、支付、用户、日志和运维页面的内容区重排。
- 创作首页、项目、素材、技能与画布视觉改造。
- 新增接口、数据库字段或设置项。
- 将 Ant Design Pro 示例代码或 Umi 运行时复制到项目。
- Headless UI 在创作端的引入。

## 3. 设计原则

### 3.1 一套产品，两种工作模式

后台与创作端共享 HMaigc 的字体、语义状态、控件尺寸、圆角和交互反馈，但允许不同的页面背景与信息密度：

- 后台：浅色企业运营界面为默认，强调扫描效率与数据可信度。
- 创作端：继续保持深色沉浸式工作台，本阶段不修改。

后台深色主题是同一套语义 Token 的映射，不是另一套页面 CSS。

### 3.2 内容优先

- 页面层级由背景明度、留白、字体和弱分隔表达。
- 一个独立区域最多一层可见边界与圆角。
- 不使用圆角卡片套圆角卡片、重阴影、渐变或装饰性图标底座。
- 指标、趋势和表格按业务重要性排序，不为了“铺满首页”添加无效卡片。

### 3.3 单一路径

- 后台主题只由一个后台主题控制器拥有。
- 后台公共结构只由 `AdminShell` 与 `AdminPageFrame` 提供。
- 页面不得自行复制顶部栏、标题区、筛选容器或主题切换逻辑。
- 第一阶段不保留旧后台外壳的平行渲染分支。

## 4. 信息架构与页面骨架

### 4.1 桌面布局

- 视口宽度至少 1280px 时显示固定侧栏。
- 展开侧栏宽 236px，折叠侧栏宽 64px。
- 顶部栏高 56px，固定在后台主内容顶部。
- 页面框架最大宽 1304px，包含左右各 32px 内边距，对应 1240px 有效内容宽度。
- 超宽屏内容居中，不无限拉伸表单、指标和表格。

### 4.2 顶部栏

左侧顺序：

1. 侧栏折叠按钮。
2. 当前业务域。
3. 当前页面面包屑。

右侧顺序：

1. 浅色 / 深色主题切换。
2. 返回创作台。

主题切换必须有可访问名称和当前状态，不仅依赖图标或颜色。

### 4.3 移动与中等宽度

- 小于 1280px 时使用 56px 顶栏和 320px 左侧抽屉导航。
- 顶栏、抽屉导航和关键操作热区不低于 44px。
- 页面标题和操作区自动换行，操作按钮不得挤压标题。
- 筛选条件收为单列或规则网格。
- 宽表格只允许在表格内容区横向滚动，不得撑宽页面或被页面裁切。

### 4.4 页面通用顺序

数据型页面统一使用：

1. 页面标题、说明与页面级操作。
2. 核心指标概览。
3. 筛选工具栏。
4. 趋势或业务分析区。
5. 数据表格或明细区域。

设置型页面在后续阶段统一使用“左侧职责说明 + 右侧字段网格”，本阶段不批量重排现有设置页。

## 5. 主题与视觉 Token

### 5.1 浅色后台基线

- 页面背景：`#f5f7fa`
- 主内容表面：`#ffffff`
- 次级表面：`#fafafa`
- 主文字：`#1f2329`
- 次级文字：`#646a73`
- 弱文字：`#8f959e`
- 弱分隔：`#e8eaed`
- 品牌主色：沿用 HMaigc 的全局品牌 Token，不在页面写死 Ant Design 蓝色。

### 5.2 深色后台基线

深色后台消费根设计真源的现有深色语义 Token。不得通过滤镜、透明黑覆盖或页面私有十六进制颜色模拟深色主题。

### 5.3 尺寸

- 页面间距：24px。
- 页面水平内边距：桌面 32px，移动 16px。
- 内容表面内边距：20–24px。
- 页面标题：22px / 30px / 600。
- 区域标题：16px / 24px / 600。
- 正文：14px / 22px / 400。
- 辅助文字：12px / 18px / 400。
- 常规控件：36px 高、8px 圆角。
- 紧凑表格操作：32px 高。
- 页面表面：8px 圆角。
- 只保留一档轻阴影，普通工具栏和表格不同时使用边框与阴影。

这些原始值必须进入现有设计 Token 或后台语义映射，业务页面只消费语义变量。

## 6. 后台主题状态

### 6.1 状态模型

后台主题只有两个明确值：`light` 与 `dark`。

- 首次访问后台且没有后台主题记录时使用 `light`。
- 管理员切换后写入独立的浏览器持久化键。
- 后台主题不得修改创作端当前主题偏好。
- 离开后台后，创作端继续使用原有全局主题。

### 6.2 作用域

- `AdminShell` 是后台主题作用域的唯一根节点。
- Ant Design 后台组件需要获得与该作用域一致的算法和 Token。
- 禁止仅切换 CSS class 而让 Ant Design Portal、Modal、Drawer、Dropdown 继续使用另一主题。
- 主题切换必须覆盖侧栏、顶栏、正文、表格、弹层和移动抽屉。

## 7. 数据概览样板页

### 7.1 页面结构

样板页按以下顺序重新排列：

1. 页面标题“数据概览”和说明“活跃、调用与成本趋势”。
2. 页面级操作：刷新、导出 CSV。
3. “运行概览”与“商业指标”组成连续指标区，避免八个独立浮动卡片。
4. 时间、用户、模型、渠道、能力组成单层筛选工具栏。
5. 使用趋势图表区域。
6. 模型分析、用户活动、异常定位标签页与表格。

### 7.2 指标区

- 使用一层白色连续表面和弱分隔。
- 每项包含 12px 标签、24–28px 主值和可选 12px 辅助事实。
- 状态不能只依赖红绿颜色，必须保留文字。
- 队列、冻结积分和异常数量使用克制的状态标签，不使用装饰性图标卡。

### 7.3 筛选工具栏

- 搜索或主要筛选占据剩余宽度。
- 同类下拉框使用一致宽度和 36px 高度。
- “刷新”“导出 CSV”移到页面级操作区，不和筛选字段挤在同一层。
- 筛选值继续使用现有 URL/组件状态和接口参数，不改变数据契约。

### 7.4 趋势与明细

- 趋势图与明细表各自只拥有一层内容表面。
- 图例、坐标、Tooltip 适配浅色和深色后台主题。
- 表格继续使用现有数据和分页，不改变统计口径。
- 加载、空数据与失败状态继续是三个独立事实状态。

## 8. 组件职责

### 8.1 `AdminShell`

- 后台主题作用域。
- 桌面侧栏与移动抽屉。
- 顶部栏、面包屑、主题切换和返回创作台。
- 不加载具体业务数据。

### 8.2 `AdminPageFrame`

- 页面最大宽度、内边距和滚动边界。
- 页面标题、说明和操作区。
- 可选模型中心页签。
- 不定义具体页面卡片和业务布局。

### 8.3 后台主题控制器

- 读取默认值与持久化值。
- 切换后台根 class/data attribute。
- 为后台 Ant Design 组件提供一致 ThemeConfig。
- 不复用创作端的主题状态作为后台默认值。

### 8.4 数据概览内容组件

- 保留现有数据请求、筛选、图表和导出行为。
- 只重排展示结构并消费公共后台语义组件。
- 不新增统计口径或伪造指标。

## 9. 可访问性与状态

- 侧栏折叠、主题切换、移动菜单均使用原生按钮与明确 `aria-label`。
- 当前导航项使用 `aria-current`。
- 跳到主要内容链接继续保留。
- 浅色和深色普通文字对比度达到 WCAG AA。
- 加载状态使用骨架；失败显示真实原因与原地重试；空状态说明没有数据。
- 键盘可完成导航、主题切换、筛选和标签页操作。
- `prefers-reduced-motion` 下不依赖大幅动画表达状态。

## 10. 数据、安全与运营影响

- 本阶段不修改 API、数据库、权限、审计、计费或任务状态。
- 主题偏好只保存在当前浏览器，不包含敏感信息。
- 导出、筛选和刷新继续调用现有受权限保护的后台接口。
- 任何加载失败必须显式展示，不用默认数据或空卡片掩盖错误。
- 不添加分析脚本、第三方字体请求或外部主题资源。

## 11. 验收标准

### 11.1 视觉与布局

- 1440×900：固定侧栏、56px 顶栏和 1240px 有效内容区正确。
- 1024×768：切换为移动顶栏与抽屉，页面没有横向溢出。
- 390×844：标题、操作、筛选和指标均可阅读，主要热区不低于 44px。
- 浅色和深色主题均覆盖页面、侧栏、Ant Design 弹层和图表。
- 数据概览符合“标题/指标/筛选/趋势/明细”的顺序。

### 11.2 行为

- 首次后台访问默认浅色。
- 主题切换刷新后保持。
- 后台主题不修改创作端主题。
- 侧栏折叠、移动抽屉、面包屑和返回创作台保持可用。
- 筛选、刷新、导出、页签和表格行为与改造前一致。

### 11.3 工程门禁

- 改动文件通过 Prettier 与 TypeScript。
- 受影响组件测试覆盖后台主题、作用域、标题操作区和数据概览结构。
- Web 全量测试和生产构建通过。
- 包体预算不回退。
- Docker 本地镜像重建后 Web 与后端健康。
- 真实浏览器完成 1440、1024、390 三个视口和两种主题验收。

## 12. 变更预算

- 生产职责：后台主题作用域、公共外壳、数据概览样板，共 3 项。
- 预计生产文件：6–8 个。
- 预计净新增或替换：500–800 行。
- 不新增超过 500 行的生产文件。
- 最终昂贵门禁：Web 全量测试、生产构建、镜像重建和一次浏览器矩阵。
- 若生产文件超过 12 个、净新增超过 1200 行，或需要修改业务接口/数据库，则停止第一阶段并重新拆分设计。
