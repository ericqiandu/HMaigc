# 筷子科技统一模型中心设计

## 1. 业务目标

将当前分散在“筷子科技”“AI 模型”和“商业定价”中的日常配置，收敛为一个面向运营人员的“筷子科技模型中心”。管理员只需完成账号验证、录入供应商成本与目标毛利率、核对售价预览并确认发布，即可让模型进入用户画布。

本次改造解决以下确定问题：

- 模型已登记、已启用但因价格档位缺失而不在画布出现，页面却没有指出缺少的档位。
- 发布、启用、成本和积分售价分属多个入口，任何一步遗漏都会形成表面成功、实际不可用的状态。
- 视频模型需要按能力矩阵配置多个价格档位，运营人员容易漏配普通生成或参考视频价格。
- 低毛利需要明确提示和审计，但不应强制禁止管理员发布。

## 2. 范围与边界

### 2.1 本期范围

- 仅整合 `kuaizi` 供应商。
- 复用现有公共 Base URL、统一 write-only Key、凭据验证和余额事实。
- 从后端 provider registry 动态读取模型及能力，不在前端维护模型枚举。
- 在同一页面维护供应商成本区间、目标毛利率、售价预览、发布与停用。
- 根据模型能力自动生成完整计价规格，尤其是视频的分辨率与输入类型组合。
- 以单一后端事务保存供应商成本、用户售价、启用状态、价格版本和审计记录。

### 2.2 明确暂缓

- 不改变模型调用、任务状态机、积分冻结/结算和资产持久化链路。
- 不整合其他供应商；原“渠道管理”和“商业定价”继续服务非筷子渠道及高级运营场景。
- 不自动抓取供应商价格，不根据上游响应自动改价。
- 不自动发布，不在管理员未确认时隐式启用模型。
- 不提供模型自动降级、默认价格或缺档位兜底。

## 3. 单一事实源

- 服务地址、凭据版本、验证状态和余额：沿用 Provider Account 领域事实。
- 模型身份与能力矩阵：以后端 provider registry 为唯一事实源。
- 模型发布、启用、访问策略、计费方式、售价和价格版本：沿用 `ChannelModel` 与价格档位事实。
- 供应商成本：沿用 `ModelPricing` 与成本档位事实，并将成本从单值扩展为最小值和最大值。
- 每积分收入价值、核算币种和全局目标毛利率：沿用 `ModelPricingOperationsSetting`。
- 管理员发布输入中的模型目标毛利率必须持久化，供重新编辑、审计和价格变化比较使用；不得只保存在前端。

旧入口与统一模型中心操作同一组事实，不建立兼容层或双轨数据。筷子模型的日常入口只展示统一模型中心；通用页面仍可查看，但不得产生相互覆盖的第二套保存语义。

## 4. 定价规则

### 4.1 成本输入

每个计价规格输入：

- 最低供应商成本；
- 最高供应商成本；
- 目标毛利率，默认继承全局 40%，可按模型调整。

当经营参数尚未配置时，页面预填 40% 但保持未保存状态，必须由管理员明确保存；已有全局目标毛利率时继续使用现有真实值，不被本次改造覆盖。

约束：成本必须大于等于零，最高成本不得低于最低成本。发布时所有必需规格的最高成本必须大于零。成本以核算币种的 micros 整数保存，前端金额只负责精确换算，不使用浮点金额作为持久化事实。

### 4.2 自动售价

售价始终使用最高供应商成本计算：

```text
目标收入 = 最高供应商成本 / (1 - 模型目标毛利率)
积分售价 = 向上取整(目标收入 × 1,000,000 / 每积分收入价值)
```

模型目标毛利率必须处于 `0% <= margin < 100%`。向上取整确保取整后不会低于目标收入。预览同时展示最低成本、最高成本、积分售价、按当前每积分收入价值折算的收入，以及按最高成本计算的预计毛利率。

### 4.3 低毛利处理

当模型目标毛利率低于全局目标毛利率，或取整后的实际毛利率低于全局目标毛利率时：

- 页面展示明确警告，但不禁止发布；
- 发布按钮进入二次确认，列出受影响模型与档位、最低毛利率、操作后生效范围；
- 后端审计保存操作人、成本区间、积分售价、模型目标毛利率、全局目标毛利率和确认时间。

无成本、成本非法、档位缺失、每积分收入价值缺失或凭据不健康属于事实不完整，必须禁止发布；这些不是低毛利警告。

## 5. 能力驱动的价格规格

价格规格由 registry 能力生成，前端不得猜测：

- 文本模型：本期采用一个“估算单次请求”成本区间和固定请求售价。
- 图片模型：按 registry 提供的分辨率生成规格；若模型只声明统一价格，则使用一个普通生成规格。
- 视频模型：对 registry 中每个受支持分辨率生成 `普通生成` 与 `参考视频` 两个规格，按秒计价。
- 不支持的分辨率或输入类型不展示、不保存，也不能被请求到。

例如 Seedance 2.5 支持 480P、720P，则自动生成四个档位：

- 480P · 普通生成；
- 480P · 参考视频；
- 720P · 普通生成；
- 720P · 参考视频。

能力矩阵变化后，旧价格不能静默复用。页面标记“能力已变化”，保留仍匹配的草稿，要求管理员补齐新规格并再次确认发布。

## 6. 页面与交互

页面路径保持 `/admin/providers/kuaizi`，标题改为“筷子科技模型中心”。信息按以下顺序单层展示：

1. **账号状态条**：Base URL、Key 指纹、验证状态、余额与“重新验证”操作；低频编辑放入一个设置弹层。
2. **经营参数**：核算币种、每积分收入价值、全局目标毛利率。已有值直接显示；缺失时在发布前明确要求配置。
3. **模型列表**：按 registry 系列分组，但每个模型独立显示状态、能力摘要、成本完整度、售价、毛利率和操作。
4. **模型定价抽屉**：只展示该模型真实需要的成本规格、模型目标毛利率和实时售价预览。
5. **发布确认弹层**：展示将创建或更新的模型、价格版本、档位和低毛利警告；确认后一次提交。

模型状态使用闭集：

- `账号未就绪`：Base URL/Key/验证不完整；
- `待配置成本`：至少一个必需成本规格缺失；
- `待发布`：事实完整但尚未启用；
- `已启用`：公共目录可见；
- `已停用`：价格保留但用户不可见；
- `能力已变化`：registry 与已发布价格规格不一致；
- `配置异常`：服务端返回不可解释的矛盾事实。

页面必须直接列出不可发布原因，例如“缺少 720P · 参考视频最高成本”，不得只显示“未定价”。写入期间锁定同一模型操作；刷新失败时保留上次成功事实并原地显示失败，不渲染空目录。

## 7. 后端契约与事务

新增一个面向筷子模型中心的聚合读取契约，返回：

- Provider Account 状态；
- registry 模型能力；
- 已发布 ChannelModel；
- 供应商成本区间；
- 经营参数；
- 服务端计算的完整度、售价预览、毛利警告和公共可见状态。

价格计算必须由后端纯函数完成，前端只展示后端预览；提交时后端使用同一函数重新计算，禁止信任前端传入售价。

发布命令只接收管理员输入事实：模型标识、各规格成本区间、模型目标毛利率、期望启用状态，以及低毛利确认标记。服务端在事务内：

1. 锁定目标 ChannelModel 与相关价格事实；
2. 重新读取 registry 和经营参数；
3. 校验凭据健康、能力规格、成本完整度和请求版本；
4. 重新计算全部售价；
5. 保存供应商成本、ChannelModel、售价档位和价格版本；
6. 保存管理员审计；
7. 提交后返回新的聚合事实。

任一步失败则全部回滚。并发编辑使用版本校验，旧页面提交必须返回冲突并要求刷新，不能覆盖较新的价格。

停用模型同样经过聚合命令与审计，但不删除价格历史。重新启用前必须再次验证当前能力、成本完整度和凭据健康。

### 7.1 数据迁移

本功能需要一次可回滚的增量结构迁移：

- 成本档位新增 `supplier_cost_min_micros` 与 `supplier_cost_max_micros`；
- 模型发布事实新增 `target_margin_basis_points`；
- 保留旧 `supplier_cost_micros` 直至同一版本完成代码切换和回归，迁移成功后运行时只读取新字段，不维护双轨写入；
- 对现有成本记录执行确定性回填：`min = max = supplier_cost_micros`，因此迁移前后的售价与毛利事实不改变；
- 迁移前后必须验证记录数、非负约束和 `max >= min`；任一校验失败则启动失败并保持原数据，不得以零值继续。

这是结构变更与批量回填，实施前必须获得用户对该准确范围的明确授权；不包含删除列、删除价格或重算现有用户订单。

## 8. 错误、安全与审计

- Key 继续 write-only，聚合 DTO 不返回明文或密文。
- 所有写操作要求管理员权限。
- 上游验证失败、余额不足、成本缺失、版本冲突和事务失败必须使用不同错误码与中文原因。
- 低毛利确认只允许绕过毛利警告，不允许绕过凭据、成本、能力、价格计算或并发校验。
- 审计不得记录 Key；必须记录模型、能力版本、成本区间、自动售价、毛利率、启停变化和价格版本。
- 公共模型目录仍以“已启用 + 完整价格 + 可访问策略 + 健康凭据”为准，统一页面不得放宽商业门禁。

## 9. 验收标准

- 新管理员从空配置到模型出现在画布，只需在统一页面完成账号验证、成本录入和一次发布确认。
- 视频模型的全部 registry 价格档位自动出现，漏填任一档时页面精确指出缺项且服务端拒绝发布。
- 使用成本上限和模型目标毛利率计算出的积分售价，与后端持久化值完全一致。
- 低于全局目标毛利率时出现二次确认；确认后允许发布并形成完整审计。
- 发布事务任一步故障时，成本、售价、启用状态、价格版本和审计均不产生部分写入。
- 两个管理员并发编辑时，后提交的旧版本不会覆盖新版本。
- 发布成功后重新读取公共目录，目标模型立即可见；停用后立即不可见。
- 图片、视频、文本模型分别覆盖完整、缺成本、低毛利、能力变化、停用和并发冲突场景。
- 现有模型调用、扣费、任务、资源和其他供应商配置回归通过。

## 10. 变更预算

- 生产职责：聚合读取/预览、原子发布命令、统一管理页面，共 3 个。
- 预计生产文件：6–8 个。
- 预计净新增生产代码：500–750 行。
- 只在稳定里程碑执行全量 Go/Web、真实数据库和浏览器门禁；日常使用聚焦测试。
- 若实现需要超过 12 个生产文件、1,200 行净新增生产代码或引入新的平行定价表，立即停止并重新拆分设计，不继续补丁扩张。
