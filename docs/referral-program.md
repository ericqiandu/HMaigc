# 邀请有礼运营说明

## 业务边界

“邀请有礼”只处理新用户邀请与首购双边积分，不包含推广返佣、现金结算或多级分销。

- 邀请码只在本地注册或 Linux.do 首次注册时绑定。
- 一个受邀用户只能绑定一个邀请人，注册后不可补绑或改绑。
- 只有受邀用户首笔已支付的个人会员订单触发奖励。
- 团队会员、续费、重复购买和退款后重购不重复发放。
- 当前奖励进入现有长期积分账户，不声明积分有效期。

## 上线步骤

1. 进入“管理后台 → 邀请有礼”。
2. 为每个已上架个人付费套餐填写“好友奖励积分”和“邀请人奖励积分”，逐项保存并启用。
3. 确认所有套餐规则均已启用后，再开放邀请活动。
4. 用户可从首页右上角礼物入口复制专属注册链接。

活动关闭后不再接受新的邀请码绑定，已绑定关系与历史奖励记录仍保留。

## 一致性与幂等

会员订单开通、会员套餐积分、邀请人积分、受邀人积分和邀请奖励记录在同一数据库事务内写入。支付回调重复投递、人工重复核款或并发订单不会重复发放同一受邀用户的首购奖励。

每次邀请奖励生成两条独立积分流水：

- `referral_inviter_reward`：邀请人首购奖励；
- `referral_invitee_reward`：受邀人首购奖励。

奖励记录以邀请关系和会员订单分别建立唯一约束。若已绑定且待奖励的用户购买了缺少生效奖励规则的个人套餐，订单履约会显式失败并保持待处理状态，管理员完成规则配置后可重试，不会静默跳过奖励。

## 风控与审计

- 注册时记录绑定 IP，仅作为后台核查证据，不作为自动封禁依据。
- 管理员只能在发奖前取消奖励资格，必须填写原因。
- 取消资格不删除邀请关系，也不会修改已发放积分。
- 活动状态、套餐奖励规则和取消资格操作均写入管理员审计日志。
