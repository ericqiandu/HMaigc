# HMaigc 工作流程记忆

## 开始任务

1. 读取 `.agents/memory/hmaigc/index.json`、`AGENTS.md` 和任务相关真源。
2. 执行只读工作区盘点，区分既有用户改动、当前任务改动与可再生输出。
3. 对话上下文仅保留本轮目标、当前事实和下一步；历史发布、视觉标准和运行约束只引用本地真源，不在会话中重复粘贴。
4. 明确业务目标、领域边界、前后端契约、数据库影响、权限/计费/审计影响与回滚边界。
5. 复杂任务维护可核验计划；每阶段完成后更新事实状态，不编造进度。

## 实施原则

1. 优先调整职责边界和共享契约，再修改具体页面或报错点。
2. 保持单一路径与最小必要复杂度；禁止为了“先能用”增加长期补丁。
3. 文件按单一职责拆分，公共逻辑提取为可测试的纯函数或领域服务。
4. 只修改任务范围内文件，不覆盖或回滚用户的其他工作。

## 验收门槛

1. 对照原始需求、计划、实际 diff、接口契约、数据库和文档逐项复核。
2. 执行与风险匹配的格式/类型检查、单元测试、构建和受影响流程回归。
3. 发布相关改动额外验证 Docker 镜像、静态资源完整性、SPA 路由、健康检查、升级与回滚路径。
4. UI 改动按桌面、平板、手机以及明暗主题检查排版、焦点、溢出、空态、错误态和可访问性。
5. 验证失败必须继续修复或明确阻塞，不得以待办代替本次应完成项。

## 提交与发布

1. 更新 `CHANGELOG.md` 的未发布区；只有正式发布时才写入版本小节并同步 `VERSION`。
2. 暂存前逐文件核对范围，确保无密钥、数据库、缓存、构建产物和无关改动。
3. 使用 Conventional Commits；一个提交只表达一个完整交付意图。
4. `push`、标签、发布、合并与云端升级必须获得用户当次明确授权。
5. 云端更新前必须先完成本地同构验证；更新后执行健康检查并确认回滚点真实可用。

## 域名与静态资源变更验收

1. 新增或切换生产域名时，先明确唯一主域名、旧域名跳转策略、OAuth 回调域名与支付通知域名；不要仅修改 CORS 或反向代理中的其中一项。
2. 静态资源使用 OSS 时，先从线上 HTML 中提取实际静态资源 URL，确认其 Bucket 与正在配置的 Bucket 一致；不得凭 Bucket 名称猜测。
3. 对每个正式 Web Origin 执行 `curl -sS -D - -o /dev/null -H 'Origin: <origin>' '<static-asset-url>'`，确认返回对应的 `Access-Control-Allow-Origin`；无此响应头即视为发布失败。
4. 旧域名跳转必须保留路径和查询参数，并分别验证 HTTP、HTTPS、首页、登录页和会员页；主域名验证健康检查、静态脚本与 SPA 路由。
5. 支付/登录上线前，校验支付商户后台与 OAuth 开放平台登记的域名、回调 URL、HTTPS 证书、应用实际配置完全一致；未实现的通道必须显式显示未接通，禁止仅保存参数就宣称可收款或可登录。

## 项目清理

1. 先用 `git ls-files`、`git check-ignore` 和引用搜索判断文件归属。
2. 只删除已确认可再生、未跟踪、未被正式链路引用的输出。
3. 禁止使用仓库根目录通配符做递归删除；逐个校验绝对路径位于仓库内。
4. 保留 `.local/`、正式部署脚本、质量门禁脚本和受版本控制的验收证据。
5. 清理后运行 `git status` 与必要验证，确认没有误删源码或正式资产。
