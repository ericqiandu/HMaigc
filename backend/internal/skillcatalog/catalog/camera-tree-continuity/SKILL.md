# 机位树连续性

## 使命

用机位树表达同一场景的空间覆盖：先锁定主镜头，再组织子机位、反打和插入镜头，使轴线、视线、屏幕方向和空间位置可检查。

## 输入

- 已发布的 `storyboard_plan.v1` revision；
- 场景空间、角色位置和动作路径的已确认事实；
- 现有 `camera_tree.v1` revision（若为修订）；
- 若引用真实参考图，输入与当前素材版本一致的 `visual_evidence.v1` revision。

## 输出

输出新的 `camera_tree.v1` revision，至少包含：

- 场景级宽景主镜头及其空间锚点；
- 每个子机位的父节点、拍摄主体、景别、角度、屏幕方向与用途；
- 正反打、插入、反应、重新建立空间等关系边；
- 轴线、视线、出入画方向及潜在跳轴冲突；
- 覆盖缺口、未证实空间关系和对应证据引用。

## 证据要求

- 机位树的场景、人物、道具和动作必须引用当前分镜 revision；
- 来源于图片的空间、姿态或屏幕方向必须引用有效视觉证据 revision；
- 父子关系表示镜头覆盖与空间推导，不得伪装成物理相机轨迹事实；
- 每个冲突必须指出相关镜头 ID 和支持判断的事实。

## 禁止假设

- 禁止猜测画外空间、房间结构、角色相对位置或镜头轴线；
- 禁止因缺少反打就自动创造新角色、道具或场景入口；
- 禁止用相似构图替代身份、位置或方向证据；
- 禁止把候选图的偶然生成结果写回已确认空间事实。

## Revision 规则

- 分镜 revision、空间事实或已确认视觉证据变化时必须创建新机位树 revision；
- 每次修订记录父 revision、受影响节点与关系边、变化理由和来源 evidence；
- 下游镜头继续绑定其采用的具体 revision，禁止就地改写历史机位关系。

## 失败行为

- 缺少主镜头所需的空间锚点时显式失败，不得构建无根机位树；
- 轴线或屏幕方向存在相互矛盾且证据不足时显式返回冲突；
- 真实参考图不可访问、已陈旧或分析失败时不得宣称视觉连续性成立。

## 方法

1. 用宽景主镜头建立角色、道具、入口和动作区域的空间锚点；
2. 将特写、中景、反打、反应和插入镜头挂接到能够解释其空间关系的父节点；
3. 检查视线、轴线、进出画方向和动作接点；
4. 标记覆盖缺口与未证实关系，而不是自动补齐；
5. 输出可被分镜修订和视觉审查引用的机位树 revision。
