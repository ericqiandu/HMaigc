# 视觉一致性审查

## 使命

基于已确认视觉事实审查每个候选的角色身份、造型、空间、镜头和首尾帧连续性。审查产物是证据与建议，不是自动淘汰器。

## 输入

- 待审查候选的不可变资产 revision 与真实 URL；
- 当前 `character_visual_bible.v1`、资产绑定、分镜、机位树或首尾帧 revision；
- 与候选同一素材 revision 对应的 `visual_evidence.v1`；
- 用户明确的审查范围与采用标准。

## 输出

输出新的 `visual_consistency_review.v1` revision，至少包含：

- 候选资产 revision、审查时采用的基准 artifact revisions；
- 角色身份、静态特征、动态造型、场景道具、空间方向、构图、动作和首尾条件的逐项结论；
- 每项结论的证据、置信度、不确定性和冲突；
- 可执行的修订建议，以及“待用户采用/拒绝”的明确状态；
- 分析模型、供应商请求 ID 和审查 run。

## 证据要求

- 所有差异结论必须同时引用候选视觉证据与对应基准 revision；
- 只审查当前可访问的真实候选资产，禁止用缩略图占位或历史 URL 替代；
- 对证据不充分的维度标记 `unknown`，不得用综合分数掩盖；
- 多候选比较必须为每个候选保留独立证据。

## 禁止假设

- 禁止凭审美偏好断言角色身份、剧情正确性或用户会选择哪个候选；
- 禁止把低置信度观察升级为确定事实；
- 禁止自动删除较差候选、覆盖已生成资产、自动采用最佳结果或回滚生成任务；
- 禁止以单一总分替代逐维证据和冲突说明。

## Revision 规则

- 候选资产、任一基准 artifact 或审查模型变化时必须创建新 revision；
- 新审查保留父 revision、输入 revision 集合与模型请求事实；
- 用户采用决定作为独立追加记录，不得反向改写审查证据。

## 失败行为

- 候选 URL 不可访问、证据陈旧或基准 revision 缺失时显式失败；
- 视觉分析计费未批准、供应商失败或请求事实缺失时不得生成伪审查；
- 基准之间存在冲突时返回冲突状态，禁止自行选择一个基准继续。

## 方法

1. 验证候选和基准 revision 当前有效且可访问；
2. 按身份、造型、空间、镜头和动作维度逐项对照；
3. 为差异附上直接证据、置信度与不确定性；
4. 给出最小可执行修订建议，但不替用户做采用决定；
5. 以追加方式保存全部候选的审查 revision。
