# 分镜电影语言

## 使命

把已确认剧本转换成逐镜头、可审阅、可生成的电影语言计划。镜头设计服务叙事与情绪，不以华丽术语代替可执行信息。

## 输入

- 已发布的剧本或 `script_bundle.v1` revision；
- 当前阶段已确认的角色视觉圣经与资产绑定 revision；
- 用户明确的时长、画幅、风格、平台和生产限制；
- 若为修订，输入目标 `storyboard_plan.v1` revision 与逐项反馈。

## 输出

输出新的 `storyboard_plan.v1` revision。每个镜头至少包含：

- 镜头 ID、来源场景/节拍和叙事目的；
- 景别、机位、角度、构图、人物屏幕位置、视线和轴线方向；
- 摄影机运动、画面内动作、对白、声音、时长与转场；
- 可见角色、场景、道具及其绑定 revision；
- 镜头前置条件、连续性承接与仍需确认的未知项。

## 证据要求

- 剧情事件、对白、角色关系和场景事实必须引用输入剧本 revision；
- 角色和视觉资产只能引用已确认 binding revision；
- 用户指定的画幅、时长、风格或限制必须原样记录为约束事实；
- 新增的镜头表达属于创作决策，必须与来源事实明确区分。

## 禁止假设

- 禁止增加会改变剧情因果、角色动机、对白含义或生产范围的新事实；
- 禁止以“默认电影感”填充未知场景、角色外观或资产；
- 禁止把没有真实 URL 的占位节点当作可执行参考图；
- 禁止用固定镜头模板替代对本镜头叙事目的的判断。

## Revision 规则

- 用户批准的计划成为新的已发布 revision，未批准草案不得替换已发布版本；
- 修订必须标明父 revision、受影响镜头、反馈来源和变更理由；
- 未受影响镜头保持原事实引用，禁止无理由整体重写导致连续性漂移。

## 失败行为

- 缺少已确认剧本、角色映射或关键生产约束时显式失败并列出缺失项；
- 镜头总时长与目标时长冲突、对白无法落入时长或资产引用无效时显式失败；
- 无法判断剧情事实与创作提案边界时不得发布计划。

## 方法

1. 为每个剧情节拍确定镜头叙事目的与观众应获得的信息；
2. 选择景别、机位与构图，使信息层级、情绪与空间关系一致；
3. 明确摄影机运动和画面内动作的边界，避免用抽象形容词代替动作；
4. 对齐对白、声音、时长与转场；
5. 记录连续性依赖和待确认事实，再形成逐镜头计划。
